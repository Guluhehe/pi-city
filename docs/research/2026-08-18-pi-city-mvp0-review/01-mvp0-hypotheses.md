# MVP-0：可证伪假设与范围约束

## 目的

MVP-0 不是“把当前设计做成一个小样”，而是一次可能推翻当前核心交互的产品实验。它只回答一个更尖锐的问题：**非技术玩家是否愿意通过帮助 Pi 处理居民委托，主动体验并理解“新结果回来后，Pi 会重新判断”的动态循环？**

任何无法帮助回答该问题的系统、内容、美术或技术整合，都不进入 MVP-0。

## 五个可证伪假设

| 编号 | 假设 | 通过时玩家会自然说什么 | 失败信号 | 失败后的正确动作 |
|---|---|---|---|---|
| H1：动态循环 | 玩家理解 Pi 的路线会因新发现而变化，不是固定六步 SOP。 | “Pi 拿到这个后改主意了。” | “就是先图书馆、再观察台、再工具坊。” | 重写任务状态与思考塔回流演出，不加教程。 |
| H2：真实选择 | 玩家认为至少一次选择有理由，且不同选择会产生可感后果。 | “我选这里，因为我想先确认……” | “因为它亮了／游戏让我点。” | 推翻或替换该任务的核心动词。 |
| H3：结果回流 | 玩家看见工具／行动结果被带回、进入 Pi 下一次判断。 | “它带回新信息，才知道接下来做什么。” | “拿到道具就开了下一关。” | 将发现物、塔内关联、声音和下一站变化重新设计为同一因果。 |
| H4：角色与世界 | 玩家把 Pi 视为行动中的伙伴，且任务后还愿意看城市。 | “让 Pi 再去看看”“灯塔后来怎样了？” | “我点这里”“结束了就关。” | 增强 Pi 的主观反应、居民目标和永久街区变化。 |
| H5：正确映射 | 玩家能把故事中的回流现象理解为 Pi 的一般行为，而不误以为故事就是一段真实 Trace。 | “真实 Pi 也会把工具结果带回来再决定，但故事是示例。” | “这就是刚才真实跑的代码／Pi 永远按同一线路走。” | 明确教学故事边界并改写翻面卡。 |

## 三条产品判死线

以下任一项在首轮 5–8 名非技术试玩者中未通过，MVP-0 不得进入正式美术垂直切片。

| 判死线 | 最低信号 | 说明 |
|---|---:|---|
| 动态循环 | 至少 4 名试玩者能自主描述“新结果改变 Pi 下一步”。 | 这是 Pi City 的独特产品命题。 |
| 有理由的选择 | 至少 4 名试玩者能在选择前或选择后给出非“因为发光”的理由。 | 否则不是玩法，是隐藏教程。 |
| 温和绕路 | 至少 5 名试玩者遇到绕路后仍继续，并能说出世界内原因。 | 否则“无失败”只是模糊的拒绝反馈。 |

“想继续玩”与“愿看城市”是重要信号，但不应在首轮成为判死线；它们可在核心循环成立后迭代增强。

## 原型不可妥协约束

| 约束 | 原因 |
|---|---|
| 只做灯塔、邮包、喷泉三任务。 | 三个任务已足以验证观察、记忆与结果回流。 |
| 每个任务最多 4 个关键状态，最多 1 条温和绕路。 | 避免用内容量掩盖交互不清。 |
| 每个任务必须出现一次地点回访、地点跳过或顺序变化。 | 直接反制“固定 SOP”误教。 |
| 同一喷泉任务必须支持至少两个核心动词版本。 | 防止团队先入为主地相信“指下一站”。 |
| 故事事件一律带 `tutorial` 来源；不可写入或伪装成 Trace。 | 维护 Pi City 的 evidence-honest 原则。 |
| Story → Trace 只做一张因果翻面卡，不接完整 Explorer。 | 定义闭环接口而不让真实 Trace 集成吞掉 MVP。 |
| 不做自由移动、战斗、迷宫、倒计时、货币、等级与收藏系统。 | 它们不能帮助检验五个假设。 |

## 需要记录的最低数据

| 事件／观察 | 要验证的假设 | 记录方式 |
|---|---|---|
| 第一次选择前的停顿与口述理由。 | H2。 | 主持人笔记 + `choice_made`。 |
| 玩家是否自己提到“新发现”“改主意”“再想”。 | H1、H3。 | 任务后复述录音／笔记。 |
| 玩家如何描述 Pi 的主体性。 | H4。 | 逐字记录“Pi / 我 / 游戏”三类主语。 |
| 绕路后的表情、停顿、继续／退出与原因。 | H3、H4。 | 观察笔记 + `detour_seen`。 |
| 翻面卡后玩家是否能区分故事、概念与真实 Trace。 | H5。 | 两个固定追问。 |

## MVP-0 的唯一成功定义

MVP-0 成功不等于玩家全部通关，不等于美术漂亮，也不等于他们能说出 `Context`。成功意味着，一位此前不懂 Agent 的玩家在完成喷泉任务后，会用自己的语言说出近似下面的话：

> “Pi 刚刚拿回来的新节拍，让它重新知道接下来要做什么；它不是每次都按一样的路线跑。”

这句话一旦不出现，团队应该愿意推翻“指下一站”、地点布局或整个故事入口；而不是继续扩写内容来解释它。
