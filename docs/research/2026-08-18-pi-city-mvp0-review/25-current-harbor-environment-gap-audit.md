# 当前港口环境资产差距审计

## 审计结论

现有港口不是“完全没有3D模型”，但它仍然是**由若干低材质、无贴图地标 + 大量程序化基础体块拼出的可交互灰盒环境**。这解释了为何添加镜头、风筝、纸页或Pi饰件后，画面依然缺少概念图中的电影质感：当前资产没有可承接近景镜头的表面信息和模块化建筑语言。

`audit_harbor_model_complexity.mjs` 的结果显示，全部地标都没有纹理图像或动画。它们可以作为远景的剪影结构，但不能表达概念图所依赖的潮湿石板、木材、红布、窗框、皮革、铜灯和纸张等材质信息。即便增加三角面，也不会自动拥有这种表面语言。

## 与行业资产系统的差距

| 层级 | 当前项目 | 记忆风街角应具备的正式系统 |
|---|---|---|
| 灰盒/布局 | 有。喷泉、任务锚点和城市位置已经可用。 | 保留并重新排布为一条明确的近/中/远景视线。 |
| 建筑模块 | 无。远景房屋多为运行时盒体，地标GLB为固定独件。 | 需要窄屋墙段、内外角、窗段、门段、屋檐、屋顶、台阶和码头柱等可拼接模块。 |
| 过渡件 | 无系统。 | 需要高度变化、转角、斜屋顶、台阶和码头边缘的连接件，防止模块化拼装变成方格。 |
| 材质系统 | 纯色PBR材料为主；GLB也没有纹理。 | 六类共享PBR/手绘混合材质：湿石、深木、青漆、皮革、铜/玻璃、红布/旧纸。 |
| 英雄资产 | 喷泉和记忆风使用程序化基础几何；Pi也是基础体块。 | Pi GLB、红门、前景灯、风筝骨架、记忆风条带和远景船各自承担一个镜头焦点。 |
| 灯光与层级 | 全局环境较亮，多处发光物均有竞争。 | 近景实用灯、Pi帽灯、奇观和红门窗口为唯一暖光；其余环境保持冷暗并以雾退后。 |
| 动画 | 旋转、浮动、路径光点。 | Pi骨骼动作、风筝布条/纸页、远船和局部灯火在同一镜头句子中工作。 |

## 结论与边界

当前代码中的Three.js渲染能力足以加载上述模块化GLB和贴图；需要的是环境资产生产，而不是代码层再增加一套随机几何。后续正式工作应限定在 **“记忆风街角”**：一个新的小场景套件先通过质量验收，再逐章替换，而不是尝试在一次改动中把现有港口所有程序化建筑全部升级。
