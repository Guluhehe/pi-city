# 记忆风开场：画面与交互核验

## 对比素材与方法

检查素材为用户提供的 `memory-wind-before-after.png`，原始尺寸为 2560 × 720。依据从左到右的五个重叠切片读取；左半为稳定基线，右半为当前直接改造版本。

## 切片 1–2：基线结论

基线在开场阶段仍呈高曝光、低对比的广场视图。镜头主体是大体量喷泉和红色环状记忆风构件；左下出现的 Pi 只有一小段青绿色球体和两枚点状眼睛。其身体、朝向、手臂与携带物都被喷泉底座、前景建筑和画面裁边竞争性地遮挡。

因此，基线虽然表达了“这里出现异常”，却没有稳定表达“Pi 先注意到异常，并选择靠近”。在这个镜头尺度中，提包即使存在也不能作为“Pi 带着调查工具/会带回发现”的视觉信息被玩家可靠读到。

## 待检查点

后续切片将核验改版右半的：Pi的轮廓尺寸、头灯/帽檐与提包分离度；记忆风与角色的视线关系；邀请面板进入后是否仍保留世界为主、交互为辅的层级。

## 切片 3–4：改版开场的核验结论

改版确实建立了比基线更清楚的蓝调环境、暗石前景、暖色窗光与红门目的地，整体空间深度和色彩层级明显改善。Pi也不再完全贴在画面边缘，而是被置于记忆风的近侧，帽檐/头灯与两点眼睛提供了初步的“助理”识别。

但镜头仍没有把 Pi 变成第一主角。Pi约占画面高度的十分之一，且其躯干被环形记忆风、纸页、近景船坞和喷泉同时竞争。提包位于角色右下方的深色区域，轮廓与地面/停泊设施相近；即使知道它存在，也很难在首次观看时读成“Pi 正在携带可调查、可带回的东西”。

当前第一帧的实际注意力顺序更接近“红环与纸页 → 喷泉 → 红门光 → Pi”，而理想顺序应为“Pi 的抬头/头灯 → Pi手里的提包或探测物 → 纸页异常 → 红门远处承诺”。

## 切片 5：环境终点与交互留白

右侧红门、窗光和前景水道在环境叙事上有效：它们给出“这条被风吹散的线索可能通向一个地方”的远期承诺。但在第一帧里，红门的高亮面积和灯串比 Pi 的轮廓更强，容易让玩家先把它读成唯一目标，而忽略“Pi 先观察”的表演。

开场优化的验收不应只看单帧。接下来需要逐项检查：Pi是否先停顿并抬头；头灯是否在纸页靠近时产生可辨识的响应；提包是否在Pi转身/靠近时摆动并出现独立高光；邀请面板是否只在动作完成后出现，并以“和 Pi 一起看看”连接到任务，而非覆盖或替代动作。

## 当前建议

保留已落地的夜景与红门环境，但将第一次镜头的设计目标从“展示港口”改为“让玩家先读懂 Pi 的一个意图”。这要求下一轮优先修改角色尺度、前景相机、提包轮廓、动作节拍和异常物的位置；而不是继续增加更多环境灯、建筑或道具。

## 实施后第一轮复核

阶段化相机和异常构件缩放已使开场从“喷泉广角展示”收束为“Pi面对异常”的中近景。首帧中，Pi的帽灯、身体、手臂、提包和提包上的暖色微光已分离出来；玩家能够理解这里有一个准备调查的角色，而不只是一个青色球体。

邀请帧证明了仍需进行一次针对性微调：Pi在转向纸页后，身体正面离开镜头，提包再次落在身体遮挡侧。也就是说，它在首帧是可读的，却没有在“和 Pi 一起看看”出现时继续承担动作信息。后续修正应把提包从局部模型坐标的遮挡侧移到过肩可见侧，而不能简单继续增大体积或亮度。

## 最终实拍验证

邀请阶段中，提包现在在Pi转向后换到镜头可见的过肩位置；包体、锁扣、暖色微光与顶端纸页可以和Pi的转头、异常纸页及左下行动按钮共同出现。它仍是程序化代理物，而非正式贴图角色资产，但已从“不可读的小附属物”转为清楚的行动线索。

完整CI已通过：69项测试、TypeScript和生产构建均成功。此次改造没有改变教程证据隔离、任务顺序或第二章已定义的红门/档案/影院状态契约。

## 资产边界

本轮解决的是**镜头、阶段、角色比例、携带物可读性和UI时机**。它不应被误称为正式角色建模完成：现有Pi仍由基础几何、材质与小灯组成。下一步应以相同锚点替换为正式Pi GLB，并补充绑定、走路/抬头/取物三段动画和一组可换的任务携带物；这样才能把已验证的演出逻辑转为可持续的美术生产。
