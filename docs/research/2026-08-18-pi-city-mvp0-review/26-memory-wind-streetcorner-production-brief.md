# Pi City「记忆风街角」正式环境美术生产简报

## 1. 决策：从“场景代码”转向“可组装的美术套件”

Pi City 下一阶段不应继续把港口视为一张可加元素的背景图，而应把它当作一套可在实时引擎中反复组装的环境资产系统。行业流程通常先在引擎中锁定相机、比例和主视线，再将通过灰盒验证的结构拆成模块化网格、英雄资产和共享材质；这样，概念图的构图会在昂贵的细化开始前受到检验。[1] [2]

> **本项目的生产决策：保留Three.js/R3F与任务状态机；以“记忆风街角”为唯一正式环境垂直切片；先完成资产套件和真实镜头，再推广到整座港口。**

这不是一次简单的“换模型”。角色、建筑、地面、灯光和相机必须共享同一条艺术规则：**圆润而可辨认的主角，偏斜而可居住的建筑，深冷背景中的少量暖光，且每个镜头只让一个问题成为最高对比点。**

## 2. 可玩街角的空间合同

| 层级 | 空间功能 | 正式资产 | 镜头职责 |
|---|---|---|---|
| 前景 | 建立尺度和沉浸感；给玩家一个站在城里的位置。 | 1盏近景铜灯、绳结/桅杆局部、湿石板边缘、Pi。 | 可轻度失焦；形成画框，不抢奇观。 |
| 中景 | 呈现当前的“未知问题”。 | 小喷泉、记忆风条带、风筝骨架、纸页、码头柱。 | 最高的运动密度和暖色反差。 |
| 远景 | 给Pi行动一个可见目的地。 | 红门窄屋、台阶、两栋窄屋立面、窗光、远船。 | 红门窗口是唯一远处暖色终点；雾降低其他细节。 |
| 可玩路线 | 让玩家理解“下一步去哪里”。 | 由喷泉至红门的可走石板/台阶；可重用的方向灯点。 | 与Pi转身、记忆风重排和任务文本同时指向红门。 |

### 目标镜头

初始镜头必须在无UI状态下传达三个信息：**Pi 在看什么、那里为何不对劲、Pi 可以带玩家去哪里。** 相机位于Pi近似眼高，略低于记忆风，以前景灯的虚焦边缘包住画面。Pi 位于左下三分位，记忆风位于中心偏上，红门位于右上三分位。镜头不是俯瞰全城的说明图，也不能用正居中喷泉替代叙事层级。

## 3. 环境资产清单

### 3.1 模块化建筑包

以下模块为同一网格单位设计，建议以 **0.5 m** 为最小吸附单位，并以 **2 m** 作为墙段与地面的大单元。每一件都必须能在引擎中独立组合，而不是只能在一个GLB中以固定姿势存在。

| 资产组 | 首批内容 | 共享材质 | 备注 |
|---|---|---|---|
| 窄屋立面 | 2 m墙段、窗段、红门段、内外角、斜墙端、店招支撑。 | 深木、石灰墙、深青/砖红漆、窗玻璃。 | 至少有三种高度和两种窗比例，避免“整齐排列的盒子”。 |
| 屋顶与屋檐 | 直屋脊、低坡/高坡屋面、屋檐、烟囱、排水槽。 | 深色瓦片/木板、铜质排水。 | 远景主要由此形成不规则天际线。 |
| 地面和码头 | 四种湿石板、台阶、排水沟、木码头、柱、绳。 | 湿石、深木、苔藓/泥土decals。 | 近景石板应有倒角、轻微高差和粗糙度变化。 |
| 转换件 | 高差踏步、T角、门廊、台阶转角、靠墙灯座。 | 复用以上材质。 | 约占模块数量三分之一，防止空间像积木。 |
| 生活化小件 | 木桶、纸张、标牌、花盆、窗帘、靠墙箱、系船环。 | 图集/trim sheet。 | 只在镜头焦点附近使用，服务环境叙事。 |

行业环境流程中，模块化套件、可平铺材质和trim sheet应在同一个审查环节被设计；否则会出现重复、缝隙和过多独立材质。[1] [3]

### 3.2 英雄资产

| 资产 | 规格 | 不可妥协的视觉职责 |
|---|---|---|
| Pi GLB | 3k–8k三角面；身体、脚、手臂、提灯帽、双肩包、纸页槽分网格；五类材质；一套骨架。 | 在黑色剪影、手机宽度和逆光下仍被识别为“提灯帽 + 双肩包 + 短腿的助理”。 |
| 红门窄屋 | 4k–8k三角面；不规则门框、窗、台阶、坡屋顶、局部爬藤/绳索。 | 不是一栋普通建筑，而是记忆风路线的远方承诺。 |
| 记忆风 | 曲线条带、红布风筝骨架、双面纸片、光点；局部动态。 | 既能散开表示未知，也能在Pi带回新事实后重排成路线。 |
| 前景灯 | 铜/黑铁灯架、磨砂玻璃、绳结与轻微摇摆。 | 提供镜头画框和暖色尺度，近景可虚焦。 |
| 远景船 | 低细节船体、桅杆、少量暖窗。 | 只承担港口深度，避免消耗近景资产预算。 |

### 3.3 材质与贴图包

环境不应再通过“每个物件一段十六进制颜色”获得外观。正式包为六类共享材质：湿石、深木、哑光青漆、棕皮革、铜/磨砂玻璃、红布/旧纸。每类至少拥有基础色、粗糙度和法线（或手绘表面替代）；近景英雄资产可有独立贴图，远景与模块使用tileable/trim sheet。行业案例普遍将粗糙度差异、笔触/边缘变化、局部decals和共享trim sheet用于让大规模模块化环境保留一致性与表面层级。[1] [4]

## 4. 电影化实时渲染规则

| 规则 | Pi City标准 | 当前需避免的做法 |
|---|---|---|
| 色彩脚本 | 约70%深冷蓝/青作为环境；约20%暖木/石中间色；约10%琥珀灯、Pi眼睛、红门和记忆风高光。 | 大面积高饱和纯色房屋与平均环境亮度。 |
| 光源预算 | 1组冷月/天光，1组主暖前景灯，少量有叙事职责的窗光与奇观光。 | 每个地标都放一个强点光源；以Bloom补救轮廓。 |
| 景深与雾 | 前景灯/绳可轻度虚焦；远景雾降低几何信息；Pi和奇观保持清晰。 | 将整张画面均匀锐化，或用浓雾掩盖中景几何缺陷。 |
| 表面反应 | 湿石反射窄而破碎的灯光；木/布保持高粗糙度；铜有受控高光。 | 所有材质同样粗糙、同样发光，导致塑料感。 |
| 后期 | 仅用于压缩动态范围、轻度Bloom和色彩分离。 | 依赖大Bloom、泛光和滤镜把基础几何伪装成电影画面。 |

## 5. 生产阶段与验收门

| 阶段 | 可交付物 | 通过条件 | 不通过时的处理 |
|---|---|---|---|
| A. 镜头灰盒 | 现有Three中可走的街角灰盒；三张同相机截图。 | Pi、记忆风、红门在无UI截图中有清晰三层关系。 | 先改相机/比例/视线，不开始细模。 |
| B. 模块装配测试 | 墙/屋顶/台阶/地面/转角的最小模块集在引擎中拼出三种街角。 | 无缝、无明显重复、红门位置可变。 | 补转接模块或修改网格单位。 |
| C. 材质Lookdev | 六种共享材质在夜、暖灯、奇观光下的对照截图。 | 湿石、木、铜、布、皮革一秒可区分，环境不泛白。 | 先改材质/贴图与色彩管理，不增加光源。 |
| D. Pi资产接入 | Pi GLB与三段短动画接入既有状态机。 | `observe`、`take-note`、`turn-and-trot` 分别表达看见、带回、改路。 | 回到角色剪影或骨架，不用发光球替代动作。 |
| E. 完整垂直切片 | 一次真实任务过程与完成后的城市变化。 | 玩家无需阅读技术术语也能说出“Pi看见问题、带回线索、城市给出下一步”。 | 找到最先失败的镜头/资产层级，局部返工。 |

## 6. DCC与运行时职责划分

| 工作 | 推荐工具/位置 | 原因 |
|---|---|---|
| 角色、建筑、红门、台阶、屋顶、灯具建模 | Blender或等效DCC，导出GLB。 | 需要稳定轮廓、UV、材质分区、骨架与动画，不应在运行时基础几何中拼装。 |
| 高模细节/烘焙/材质 | Blender + Substance Painter/Designer 或手绘纹理工具。 | 将倒角、木纹、湿石、皮革、铜和纸张信息高效带入低模。 |
| 模块拼装、相机、动态灯、雾、状态触发 | 当前Three.js/R3F。 | 现有游戏逻辑、交互、镜头和状态机可直接复用。 |
| 远景简化/LOD/实例化 | Three.js运行时与资产导出策略。 | 把浏览器预算留给Pi和镜头前街角。 |

> **明确的技术判断**：不建议因这次风格差距迁移Unity或Unreal。它们能提高制作便利性，但不会替代角色建模、材质生产、镜头灰盒和艺术审查。对于当前的网页交互玩法，正式GLB + PBR贴图 + 模块化装配在Three.js中是合理路线。

## 7. 外部资产制作交接包

交给建模师/外部供应商的包必须包含：两张视觉参考（Pi与街角）、本简报、相机截图、比例图、每个资产的网格/材质预算、GLB导出规则、贴图命名规则和三张验收姿态。首批只生产Pi、红门窄屋、前景灯、湿石地面和记忆风，不采购一整套泛用城市包。
