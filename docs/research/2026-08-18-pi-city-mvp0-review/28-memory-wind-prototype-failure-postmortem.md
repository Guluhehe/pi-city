# 记忆风程序化街角：失败复盘与纠正措施

## 结论

“记忆风街角”程序化夜景原型已经撤回，**不得进入默认体验，也不得作为正式美术进度展示**。用户对实拍的判断正确：它的观感低于此前稳定港口，远低于视觉目标图。将盒体、圆柱、纯色PBR和几盏点光放入深色环境，并不会制造电影质感，反而会让几何与材质缺陷更明显。

> 这不是再调一轮曝光、Bloom或雾能解决的问题。它是资产质量缺失导致的不可接受的视觉断裂。

## 实拍与目标图的差异

| 目标图实际依赖 | 被错误替换为 | 为什么失败 |
|---|---|---|
| 建筑的不规则轮廓、屋檐层次、窗框、台阶和道具堆叠。 | 以少量长方体、简化窗和固定单色面构成的“窄屋”。 | 远近景均缺少可读细节，建筑只剩黑色轮廓，无法形成可居住的港口。 |
| 湿石、粗木、磨损铜、玻璃、红布和纸张在同一灯光下不同的反射与粗糙度。 | 无贴图的纯色材质与统一粗糙度。 | 即使加灯，画面仍像塑料基础体，不会出现参考图中的质感和受光层次。 |
| 有明确焦外层级的前景灯、Pi、记忆风、中景泉台和远景红门。 | 在现有喷泉坐标上叠加特效，且相机仍承继广场级视野。 | 视觉重心分散，Pi和问题没有足够的镜头优先级。 |
| 具有完整轮廓、背包、帽灯、脚、手臂和真实受光的Pi英雄资产。 | 由球体、圆柱、方盒临时拼接的安全回退Pi。 | 身份锚点被理解，但没有角色建模、贴图、骨架动作与近景表现质量。 |
| 引擎中基于可用资产建立的电影光照。 | 为掩饰低模而降低全局亮度的夜景。 | 黑暗没有增加材质信息，只压低了场景可读性。 |

## 已执行的纠正动作

1. 已用 `a62018e` 回退程序化街角提交 `45834b2`。默认章节二和全部12任务恢复至已验证的稳定港口。
2. 保留此前的行业研究、资产差距审计和街角生产简报；这些是正确的生产路线，而非需要撤回的判断。
3. 后续不再提交“基础几何 + 变暗光照”作为美术升级。程序化占位物仅可用于不可见的空间/交互灰盒，不能用于画面验收。

## 新的强制验收顺序

| 门槛 | 允许开始的工作 | 禁止的工作 |
|---|---|---|
| 未获得正式资产 | 编写资产简报、在DCC中验证比例与材质、维持现有稳定画面。 | 修改默认实时场景以模拟概念图；继续调Bloom/雾/色调。 |
| 有Pi GLB与红门街角GLB | 在隔离场景导入真实网格、贴图和骨架，做一张固定相机对照图。 | 在看见真实贴图前做全城替换。 |
| 固定镜头通过对照 | 接入动画、任务状态和局部光照，录制真实交互。 | 因“功能跑通”跳过视觉审查。 |
| 完整切片通过 | 扩展模块集到港口其他区域。 | 将单张概念图的氛围当作已实现效果。 |

## 下一步

下一项工作必须是**资产制作/获取**而非实时场景继续试错。正式交接包需要包含Pi英雄GLB、红门窄屋、前景灯和记忆风套件，各自有网格、材质、贴图、骨架和动画的验收条件。获得真实资产后，先在DCC或隔离浏览器镜头中做“目标图—资产—实拍”三联对照；只有对照通过，才重新开启运行时改造。
