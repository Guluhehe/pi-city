# 喷泉街：多地点 3D 调查垂直切片

## 目标

喷泉任务不应停在一张背景图或一组覆盖在画面上的问题卡。这个垂直切片将它变成一块可以反复观看、选择调查方向、看 Pi 出发并看城市变化的小型 3D 街区。它复用 Pi City 已有的港口世界：镜头、光照、程序化建筑、港口物件、角色群、`arrival-harbor.glb`、`session-archive.glb`、`model-core.glb` 远景地标和 3D 场景切换，而不为教学故事再造一套平行的网页游戏。

玩家不是直接操控 Pi 走路。玩家在 3D 街区里指认一个尚未弄清的现象；Pi 解释计划，自己走向该地点并带回物件。每次带回后，镜头回到喷泉广场，已访问地点留下一枚手账印记，尚未解决的地点仍可被回访或选择。

## 街区地图

| 地点 | 空间位置与 3D 物件 | D 机制中的作用 | 调查后的城市变化 |
|---|---|---|---|
| **喷泉广场** | 中央石制喷泉、四道水弧、纸船、乐手长椅。 | 委托、初看、每次结果回流与最终确认的中心。 | 第七拍从一根缩短的水弧变为完整水弧；结局增加金色水光。 |
| **乐手码头** | 木质小舞台、乐谱、纸灯、音符浮标。 | “是不是还缺旋律的信息？” | 带回断拍纸带；该地点留下被标记的完整回应节拍。 |
| **水线小渠** | 浅渠、测量浮标、水滴光点和桥。 | “水压下降是原因，还是巧合？” | 带回水压规律；浮标在第七拍同步闪烁。 |
| **风铃小巷** | 立杆、风铃、飘带与小街灯。 | “风会不会吹断了声音？” | 反证路径；风铃照常摇动，地点留下“不是风”的淡色印记。 |
| **工具坊** | 低矮作坊、铜管、同步阀与工作灯。 | 两项关键发现合并后的 Pi 行动。 | 同步阀被安装，喷泉水流变稳。 |
| **晚风花园** | 石阶、风灯、花盆与可听见整首歌的小平台。 | “怎样才算真的办好了？” | 完整试演；乐手、风铃和喷泉共同出现城市回响。 |

## 空间状态与玩家节奏

初始镜头看向喷泉广场。Pi 完成初看前，唯一可互动地点是喷泉。初看后，乐手码头、水线小渠和风铃小巷的线索标记出现在各自 3D 位置；点击其中一个地点就是提出一个未知问题。非选择状态下，所有可点击地点的浮标隐藏或降低亮度，防止玩家把 Pi 的行动误解为路线管理。

当玩家选定一个地点，镜头平滑移动到该地点，Pi 的小灯笼沿一条短路径前进；这段移动不是玩家驾驶或实时控制。Pi 带回发现后，镜头总会回到喷泉广场，并在底部共同调查手账中新增物件。反证“不是风”会保留风铃小巷作为一个已访问地点，但其线索光从强色变成淡色；它不是失败、也不要求重来。

两项关键发现同时出现后，工具坊点亮。同步阀安装后，晚风花园与水线小渠都可用于最终确认；其中任一条确认都可到达结局，但另一地点仍会在手账中显示为可选的“还可以看看”。这使“工具结果回来后不一定总是改变路线”在空间上保持可能，而不被教成固定 SOP。

## 技术边界

教学街区拥有独立的 `FountainSessionState`，不读取或改写 Semantic Trace。3D 场景只消费这个确定性状态以控制镜头、热点、Pi 的位置和材质/光照；它不会显示 Trace 的事件、工具名或 Runtime 细节。顶部故事书签继续声明教学故事属性，并保留日后打开真实 Trace 翻面的接口。

本轮只将生成的喷泉街概念图作为颜色、形状和氛围参考，不在运行时作为远景贴图使用；前景的喷泉、码头、风铃、工具坊、花园、路径、热点和 Pi 均由现有 Three/R3F 代码的程序化网格实现，既有港口 GLB 则作为远景地标提供城市纵深。因此，玩家看到的不只是静态图片：镜头、地点、可点击热点、Pi 的位移、光源和任务状态都会在 3D 中改变。为保证触控、键盘和自动化环境不会因画布命中失败而卡住，世界热点保留为首选交互，同时提供内容完全一致的“去某地看看”备用入口。

## 验收

垂直切片需要在截图或试玩中清楚呈现以下内容：喷泉之外至少三个可点击调查地点；选择地点后的镜头移动和 Pi 出发；一次反证回流；工具坊解锁；结局时喷泉和花园的可见变化。若这些变化仍只能靠文字告知，3D 垂直切片视为未完成。
