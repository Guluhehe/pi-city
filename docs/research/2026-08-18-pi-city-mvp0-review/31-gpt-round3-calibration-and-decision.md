# GPT Round 3 校准：接受的裁决、需要澄清的部分与下一步最小验证

> **校准日期：** 2026-08-19  
> **输入：** `30-external-review-gpt-round3.md`，当前 `main` 的 `0ffef1d`。  
> **结论：** 接受“修改后继续第二章垂直切片；禁止扩张到全章节”的总裁决。下一阶段不做更多章节开场、不推进正式全城资产替换；只验证 Pi City 是否真正形成玩家可理解的因果。

## 一、总校准

Round 3 的判断是准确而必要的。当前第二章的实际进展发生在 **Visual Agency Layer**：画面开始让 Pi 先看见异常、表达意图，并在 UI 出现前邀请玩家同行。这是方向性成功，但不能被误读为玩法因果或 Story ↔ Trace 因果已经获得证明。

> 程序化 Proxy 现在已经足以验证镜头、角色意图、交互时机与信息可读性；它仍不足以证明最终角色、建筑或材质的美术品质。

因此，未来两类工作必须分开评价：视觉代理用于验证演出结构；正式资产用于提升最终美术质量。两者不能相互替代。

## 三、一个重要澄清：领域因果并非完全缺失，缺的是可见的因果表达

Review 3 正确指出当前三套阶段系统会漂移，但不应由此推断项目已经没有领域状态。

`city-missions.ts` 的纯 reducer 已经保证：玩家选择问题后才会进入计划；Pi 的行动完成后才把返回结果写为 `lastReturn`；玩家确认返回后，任务才依据带回的事实转入下一问题或完成。原喷泉任务甚至已有更强的 `return → action → return → complete` 例子。

真正缺失的是：**章节任务的 Presentation Beat 没有从这些领域事实中充分派生。** 当前风筝任务在返回时虽然会切到记忆风 `reframe`，但玩家仍主要通过侧栏、台词和知识卡读到“Pi 重想了”。因此下一步不是再增加一个平行“动画状态机”，而是让已有领域事实显式派生以下演出：

```text
returned-with-new-evidence
→ Pi 展示携带物
→ 两件事实/线索被放到同一观察面
→ Pi 改变朝向 / 新路线出现
→ 玩家能说明：因为带回了什么，所以 Pi 为什么改主意
```

## 四、冻结扩张后的四项 P0

| 顺序 | P0 工作 | 成功标准 | 明确不做什么 |

| 1 | Blind Opening Mode | 5–8 名非技术参与者在无文字 3 秒画面后，自发说出 Pi 在发现、观察或准备调查异常。 | 不以“他们看懂了字幕”作为通过证据。 |
| 2 | Invite 玩家门控 | 进入 invite 后不会在计时结束时回到 Dashboard；点击 CTA 或明确 skip 才离开。 | 不继续增加新的港口入口 UI。 |
| 3 | 风筝任务 Return / Re-think | 至少一条完整链路让玩家读懂“新带回物 → Pi 重想 → 新路线”。 | 不继续扩写提包材质、更多晨昏色彩或其他章节 Opening。 |
| 4 | Beat 派生适配器 | 用领域状态派生 presentation beat，并通过测试锁定映射。 | 不让 `intro/invite/explore` 继续发展成第二剧情状态机。 |

## 五、最小实施顺序

第一步先为港口开场加入 `?blindOpening=1`，或等价的显式测试入口。此入口应固定在第二章风筝任务、移除解释性伪元素与邀请卡、在 3 秒后暂停并显示中性问题“你觉得这个小角色正在干什么？”。该模式是用户研究工具，不应作为正常玩家的默认体验。

第二步删掉 16 秒自动 Explore。正常开场依旧可在 2.4 秒后出现邀请，但 invite 之后必须等待 CTA；如果需要避免停滞，只允许 Pi 保持轻量 idle 和异常纸页的循环，而不是把玩家推回总览。

第三步只选择**风筝任务的一次返回**，实现携带物落在观察点、Pi 重新观察、红门路线被重新组织的世界内三拍。此时应测试一个问题：

> “Pi 为什么后来换了一个办法？”

正确回答必须引用新带回的线索或事实，而非“红门亮了”“系统提示我下一步”。

第四步将上述开场与返回的 UI 阶段收束为 Domain State 的派生层，并为映射补单元测试。仅当这条单任务因果在无解释条件下获得真人理解证据时，才讨论把模式推广到钥匙、影院和其他章节。

## 六、对后续 GPT / 外部 Review 的边界

下一轮外部 Review 不应再讨论“还可以加哪些资产、章节或 UI”，而要审查四个可证伪命题：

1. Blind Opening 是否真的让 Pi 的意图在无解释文字下可读？
2. 玩家回应是否真的进入状态机，而不是只是一粒按钮？
3. 返回的新信息是否可被玩家连接到 Pi 的重新判断？
4. Presentation Beat 是否已由领域状态派生，而非由另一个定时剧情状态机驱动？

如果其中任何一项失败，优先修改风筝垂直切片，而不是扩大生产范围。

## 七、最终决策

**继续，但收窄。**

本轮不否定已经完成的场景改造；它验证了正确的演出方向。真正的校准是把团队的下一步从“把画面做得更精致”切换为“用最小、可观察的实验，证明玩家是否真的理解 Pi 的观察、带回与重想”。

## P0 实施验收：Blind Opening Mode 与 Invite 门控

已新增 `?story=2&blindOpening=1` 的显式盲测入口。该入口在前三秒移除顶部栏、任务邀请、解释性伪元素与“Pi 先抬头看见了它”等答案型文字，只保留港口、Pi、提包和记忆风的真实画面。三秒后才出现中性自由回答问题：“你觉得这个小角色正在干什么？”。

自动化验收已验证：盲测纯画面阶段没有泄露性文本；中性问题会在三秒后出现；正常模式进入 invite 后，超过原来的 16 秒阈值仍保持 invite；只有点击“和 Pi 一起看看”才会进入风筝任务。此模式记录的是本地受试者文字输入，主持人仍需在真实测试中单独收集、匿名化和汇总结果；它不把测试回答写入教程 Semantic Trace。

实拍复核进一步确认：正常模式在旧 16 秒阈值之后仍停留在 Pi 的邀请状态；城市信任图和任务总览不会自动回来。点击“和 Pi 一起看看”后才进入“找不到家的小风筝”任务首帧。因此目前的可见因果已从“开场播完后恢复 Dashboard”改为“Pi 表达意图 → 玩家回应 → 共同开始调查”。

## P0 实施验收：风筝任务的带回与重新判断

风筝任务现在只在 Pi 已带回“屋顶风向札记”且本次返回为“新鲜的风筝线”时进入重构演出。真实场景中的两张纸页被并置到记忆风下方，金色连接环与路线光点延伸到红门；同一时刻，任务卡和低干扰提示明确区分“旧日”与“现在”。

玩家看到的不是“红门亮了，所以该去红门”，而是“旧日风向告诉 Pi 从哪里找；眼前的风筝线告诉 Pi 现在往哪里走”。确认该重想后，状态机仍回到 `choose-question`，并由玩家选择“屋顶红门看看”；它没有自动完成最后一段调查。端到端脚本已验证两条事实、重想提示和新的红门问题均从真实的风筝任务状态派生。
