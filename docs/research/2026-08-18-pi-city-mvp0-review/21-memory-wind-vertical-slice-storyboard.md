# 第二章「记忆风」垂直切片：逐秒分镜与 Pi 表演契约

## 体验命题

这不是一段为了炫技而插入的开场动画。它必须让玩家在不到半分钟内**感到**本章的核心：过去的线索像风筝尾一样被风带着走，Pi 不会把记忆当答案，而会带着它去看现在；玩家要决定先让 Pi 看哪里。

> **玩家在 25 秒后应当说得出：**“这座城里有一阵把旧记忆吹散的风。Pi 注意到了它，正在等我指一个地方先去看看。”

镜头不需要锁住玩家。所有画面都允许跳过，且在第 5 秒后可随时点击 Pi/征兆进入当前可办心愿；20–30 秒是完整停留时的“表演上限”，不是强制等待。

## 演出对象与空间布置

| 元素 | 屏幕职责 | 三维位置与表现 |
|---|---|---|
| **记忆风（主导奇观）** | 第一眼回答“这里不对劲”。 | 在喷泉左前上方形成一个倾斜的风环：一片红色风筝尾、三张旧档案页、两颗淡金色记忆灯和一段断线。它们先散、再被 Pi 的小灯引导成一条指向屋顶的弧。 |
| **Pi（次焦点）** | 第二眼回答“谁在关心这件事”。 | 位于画面下方偏左、与风环保持前后景差；薄荷色轮廓与深色眼睛可读，背包侧对玩家。Pi 的视线与身体始终指向当前最值得注意的对象。 |
| **屋顶红门（远方承诺）** | 第三眼回答“接下来能去哪里”。 | 在远景右上方保留一扇小红门与一段未系好的风筝线；仅在第 12 秒后以极弱暖光回应，不抢主角。 |
| **码头广场（背景庇护）** | 保留温馨与安全感。 | 建筑降低饱和和明度，水面、灯串与窗口保持安静低频运动；只有与心愿有关的物件使用章节强调色。 |

## 0–27 秒逐秒分镜

| 时间 | 镜头与场景 | Pi 的表演 | 声画与交互 |
|---|---|---|---|
| **0.0–1.2 s** | 黑蓝色的港口边缘淡入。镜头位于一盏失焦路灯/旗串之后，缓慢穿过近景遮挡，先不给完整城市。 | Pi 只露出轮廓，在喷泉旁停住。 | 只有海面、布旗与远处风铃；所有大UI隐藏。 |
| **1.2–3.0 s** | 镜头落到低机位三分构图。红色风筝尾从画外掠进，随后三张档案页被吹散，风环在画面中央偏上形成。 | **动作一：看见。** Pi 先抬头，再向风环迈半步；身体向风偏转约 12°，背包随停顿轻晃。 | 一句小字世界内浮现：`“风把一段旧记忆吹散了。”`；奇观可点击。 |
| **3.0–5.0 s** | 风环短暂停在 Pi 与远景红门之间，镜头继续极轻推近。世界没有立即给出正确地点。 | Pi 看向档案页，再看向远景红门，最后回头面对玩家约 0.35 s。 | Pi 不说技术语言，只用一句：`“我们先别急着猜。”` 点击 Pi/风环或 2.5 秒后，出现一张**单卡**：`找不到家的小风筝` / `和 Pi 一起看看`。 |
| **5.0–8.0 s** | 单卡出现后，广角轻微拉开，让风环、Pi 和红门同屏，城市信息仍保持收起。 | **动作二：挑一页。** Pi 从背包里拿出一张空白记忆页，朝风环伸一下；一张档案页落入背包口，其他页仍在风里。 | 这不是奖励，而是“Pi 先拿到一个值得查的线索”。玩家点进委托即进入正式任务；不点则奇观循环。 |
| **8.0–12.0 s** | 若玩家停留，风环慢慢沿一条弧指向旧日图书馆和屋顶方向；不是箭头，而是纸页与风筝线的自然方向。 | Pi 跟随纸页转身，停在面向图书馆的一侧。 | 右下角出现低压引导：`“你想先让 Pi 弄清哪一件事？”`；章节信任图和发现册以小尺寸淡入。 |
| **12.0–18.0 s** | 三个心愿不再是满宽卡片，而是以港口中三个弱发光征兆出现：屋顶的风筝线、档案门的纸页光、广场雨棚的一滴雨。玩家点征兆后才展开相应卡。 | Pi 用轻微的头部/身体朝向切换响应玩家悬停的征兆。 | 每个征兆仅有一个简短的环境声：布料掠风、纸页翻动、雨棚滴答。 |
| **18.0–27.0 s** | 玩家若不选择，镜头保持稳定。记忆风重新散开后再聚合，形成舒缓的可循环港口状态。 | Pi 回到“看见”姿态，但每次循环的视线顺序略有不同。 | 不是倒计时，也没有催促；完整循环可无限停留。 |

## Pi 的三段动作设计

| 动作 | 叙事语义 | 动画节拍 | 技术实现建议 |
|---|---|---|---|
| **一：看见（Notice）** | Pi 不是预知答案，而是在城市里注意到一件值得查的事。 | 0.65 s：头/灯帽上抬 → 0.25 s 停顿 → 身体向风倾 12° → 小步前移 0.18 world units。 | 在 `PiCompanion` 引入 `presentationBeat='notice'`；复用 group 旋转、位置 damp 与背包摆动，无需新骨骼。灯帽环逆时针慢转一小段。 |
| **二：挑一页（Choose / Hold）** | Pi 从一团散乱记忆中取走“此刻值得带着”的一页，表现第二章不是盲信旧线索。 | 0.45 s：背包侧转向奇观 → 0.5 s：一张纸页下降并停到背包口 → 0.3 s：Pi 回身看向玩家。 | 在背包旁生成一个小型 `MemoryPage` 程序平面；由风环阵列的一页缩放/插值到背包锚点。让其色彩低于章节主色，避免变成奖励光球。 |
| **三：放回并改路（Return / Reframe）** | 当 Pi 带回新发现，它把带回物放进心愿潮汐，世界重排；这才是“新结果改变下一步”的可视化。 | 1.2 s：Pi 小跑返回 → 0.35 s：取出带回物 → 0.5 s：物件融入风环 → 0.8 s：风环改为指向新地点，远景城市给出回应。 | 扩展既有 return 逻辑：用事实色 `tokenColor` 而非白色 bloom；`WishPhenomenon` 接收 `returnKind` 与 `missionFacts`，将轨道中心从散乱螺旋插值为定向弧线。 |

## 任务状态到表演状态的映射

| 游戏状态 | 画面状态 | Pi 动作 | 允许玩家做什么 |
|---|---|---|---|
| `CityStoryHub` + 当前任务 `kite` | `memory-wind-idle` | 看见 → 挑一页 → 循环 | 点击 Pi/风环/心愿征兆开启任务。 |
| `arrival` / `first-look` | `memory-wind-close` | 看见，镜头更近 | 进入委托，听/看第一点异常。 |
| `choose-question` | `memory-wind-ask` | 面向玩家，视线朝选项对应地点移动 | 选择先调查的地点。 |
| `plan` | `memory-wind-hold` | 挑一页，背包形成一个可见槽位 | 确认 Pi 的计划。 |
| `expedition` | `memory-wind-stretch` | Pi 沿纸页/风筝线方向离开 | 等待/观看 Pi 前往。 |
| `return` | `memory-wind-reframe` | 放回并改路 | 看新发现如何重排风环，再记进手账。 |
| `complete` | `memory-wind-home` | Pi 站在已系好的风筝线下，向玩家点头 | 回码头，看屋顶线与档案门的新变化。 |

## 镜头参数与约束

| 项目 | 目标 |
|---|---|
| 主镜头 | 从高俯视总览切到略低于 Pi 视线的 3/4 侧前方。镜头将 Pi、风环、红门排成一条由近到远的斜线。 |
| 焦段 | 约 43–47° FOV；不用极广角，避免城市盒子感和石板畸变。 |
| 景深替代 | 不新增高成本后处理景深。用冷暗背景、局部暖光、空间留白、近景遮挡和阵列运动完成主次分离。 |
| 光照 | 背景：深青蓝；港口暖光：琥珀；第2章强调：风筝朱红 + 旧纸米白 + Pi薄荷。禁止新增大面积纯白 bloom。 |
| UI | 首屏 0–2.5 秒不出现信息墙；每次仅出现一项当前决策。详细信任图/发现册由玩家主动打开。 |

## 截图验收点

1. **第 2.5 秒：** 不读文字也能看出风筝/纸页形成的异常和 Pi 的关注方向。
2. **第 6 秒：** 只显示一项可做的心愿，而不是一排任务卡；Pi、奇观和目标红门均未被UI遮挡。
3. **第 14 秒：** 任选一个港口征兆，玩家可以理解“我能让 Pi 先查这里”。
4. **完成后：** 屋顶的连线、档案门的暖光在回到码头时仍可见，且风环不再是散乱状态。

## 取舍

本切片不引入自由移动、复杂骨骼、真实布料模拟、物理纸张或全城替换资产。它用当前 `FountainStoryScene`、`ChapterLandmark`、`PiCompanion`、路线灯、相机 damp 和教程状态机，优先证明**构图 + 角色动机 + 因果世界变化**可以显著提升吸引力。

## 视觉目标资产

已生成美术目标图：`assets/memory-wind-visual-target.png`。该图用于校准实时画面的**低机位构图、Pi前景轮廓、记忆风单一主导焦点、冷蓝环境与琥珀庇护光**；它不是要直接作为贴图/背景使用，也不要求重做当前的低多边形港口。实装必须用现有 Three.js 组件和程序几何保持可玩性、可复访和清晰的交互层级。

## 实装中的画面验收记录

`demo-recordings/memory-wind/01-phenomenon-notice.png` 已确认首屏不再出现全幅任务卡和大标题墙。Pi 处在可读的左下前景，眼睛、灯帽与背包成为稳定次焦点；朱红风筝尾、悬浮纸页和断线构成场景内的主导事件；喷泉高光已降为背景层而不再吞没画面。下一验收重点是 2.4 秒后的单一邀请和 9.8 秒后的城市信息展开，确保它们不会重新把注意力拉回“仪表盘”。

单一邀请帧的首轮捕获暴露出一个待修复问题：在原计划仍应展示单一邀请的时段，完整标题、信任图和三张心愿卡重新出现，说明需要对码头阶段状态做浏览器级计时诊断，而不能只依赖样式过渡。该问题不改变场景和Pi表演的实现方向，但阻塞了“世界先说话”的验收通过。
