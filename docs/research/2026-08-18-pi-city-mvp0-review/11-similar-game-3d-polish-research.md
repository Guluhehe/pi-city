# 相似游戏研究：从“可读灰盒”到“想停下来探索的 3D 小世界”

## 问题重述

喷泉街已经拥有多个实时地点、Pi 的自主移动和随任务改变的物件，但尚未形成优秀小型探索游戏常见的吸引力：**每一帧都像一个可以停下来看的地方；每一个地点都有独立的动作语言；每次进展都让玩家先看见变化，再读到变化。**

本研究不把相似游戏的截图当作可直接复制的美术资源，而提取它们的空间、材质、镜头与交互策略，并转译为能在当前 R3F 代码库中以实时几何和小型动画实现的方案。

## 参考对象与可靠结论

| 参考 | 可验证的设计线索 | 对 Pi City 的可迁移原则 |
| --- | --- | --- |
| **Alba: A Wildlife Adventure** | 环境美术从引擎内的简单几何与纯色开始；为了在保持低多边形形体的同时加强阴影区域，团队使用渐变色；大面积地面、码头与墙面再由 decal 增添材料线索；他们还通过破损边缘和成组摆放打散直线与规则感。[1] | 不必把喷泉街推向写实高模。先保留清晰轮廓，再用**少量材质差异、边缘破损、成组道具和有意构图**取代空的大平面。 |
| **Alba: A Wildlife Adventure** | 该团队以明显不同的区域让玩家感到身处不同地点；在后期又从纯程序化布置回到局部手工摆放，以获得更强的构图控制。[1] | 六个调查地点不应只是“方位不同的方块”。每一个地点需具备一项远看可识别的轮廓、两三类成组道具、一个循环动作及一个任务完成后的视觉反应。 |
| **A Short Hike** | 官方 GDC 后记将其描述为从原型发展而来的小规模作品；任天堂的产品页则强调玩家可以自行选择路径并发现沿途内容。[2] [3] | 让小空间显得可探索的关键不是地图面积，而是**远处可看到的承诺、近处可触发的微发现、短路径上的连续引导**。喷泉街应增加能从中心看见的灯、旗、纸片、烟与水面反光。 |
| **TOEM** | 开发者将其方向概括为“art-first”与非暴力：先把世界呈现为值得探索、好看的场所，再让机制增强这一感受；他们把角色、环境和情景理解为儿童绘本般的可爱小故事，并允许玩家选择喜欢的任务而非清空所有任务。[4] | 问题选择的 UI 不应主导画面。让玩家先被一盏灯、一张乐谱、一串风铃或一段水线吸引，再自然地提出“Pi 去那里看看”。反证路线要像额外的故事发现，而不是错误答案。 |

> **核心判断：** 当前版本的问题并非“低多边形不够精细”，而是它尚未把低多边形的优势——强轮廓、颜色分区、手工构图、动态剪影和可见状态变化——组合成一个有情绪的探索场景。

## 截图审查中的共同语言

对 A Short Hike、Alba 与 TOEM 的截图审查显示，它们的表面风格不同，但都遵循以下共同模式。

| 画面层级 | 优秀小型探索游戏的做法 | 喷泉街的实施约束 |
| --- | --- | --- |
| **远景** | 用单一大色调、清晰天际线或地标建立方向。 | 港口地标、暮色天空和海面必须成为背景，而不能与任务地点争夺同一对比度。 |
| **中景** | 每个区域先用大轮廓区分，例如桥、树冠、塔、屋顶、码头。 | 乐手码头是暖木与乐谱；水线是冷色浅渠与浮标；风巷是高而窄的风铃门；工具坊是烟囱和琥珀工作灯；花园是环形暖灯。 |
| **近景** | 少量成簇道具形成“有人正在这里生活”的迹象，而非均匀撒满物件。 | 每个地点只增加三到五个相关道具簇：乐谱/木桶、纸船/测量浮标、风铃/飘带、阀门/工具箱、花盆/灯笼。 |
| **动态层** | 风、水、灯、尘、角色与小动物持续提供低成本的生命力。 | 只使用轻量程序动画：水面与喷泉、纸张与飘带、浮标、烟、船、萤光、灯火、Pi 呼吸和提包。 |
| **进度反馈** | 任务完成后由区域先给出可见回应，文本用于确认意义。 | 反证后风铃的颜色由强紫转为灰银；双发现后工具坊亮灯；同步阀后喷泉水弧变稳；确认后花园与全街暖灯响应。 |

## 对当前 R3F 场景的优先级策略

### 一、从“铺满细节”转为“剪影优先的地点演员”

每个地点首先只承担一个可从喷泉广场看到的**动词**：乐谱轻摆、浮标起伏、风铃摇摆、烟囱吐烟、花灯旋转。用户在不阅读任何说明时，也能感到这些地方不是装饰，而是正在发生事的城市节点。之后才增加少量第二级道具。

### 二、以局部材质变化代替高分辨率贴图堆叠

Alba 的经验表明，低多边形环境可通过渐变、decal、破损和成组摆放获得材料感，而不必先追求昂贵贴图。[1] 喷泉街采用石板色阶、木板间隙、金属暖光、水面微反射和边缘环形细节；后续继续增加可复用的斑驳 decal 和不规则石板变体，避免把所有地面变为同尺寸网格。

### 三、将镜头视为“讲故事的剪辑”，不是展示全地图的监控器

初始镜头应让喷泉、Pi 和最靠近的异常形成三角焦点；问题选择时，地点的上升光尘与微小相机偏移给出邀请；Pi 出发时，灯点沿路亮起；Pi 回来时镜头回到喷泉并让带回物与城市状态同框。这样玩家看到的是一次冒险的节奏，而非一个常驻鸟瞰图。

### 四、让所有动态都服务 D 机制

“动态”不等于加大量循环特效。每一个变化都要回答其中一个问题：**这里为什么值得调查？Pi 去了哪里？它带回了什么？这件事改变了城市的什么？** 任何无法支持这四个问题的特效都应削弱或删除。

## 下一轮可执行的 3D 改动

| 优先级 | 改动 | 实时实现方式 | 对用户感受的预期提升 |
| --- | --- | --- | --- |
| P0 | 重新组织初始构图与石板广场 | 减少规则网格的均匀感，加入环形构图、不同尺寸石板、湿边与道具簇。 | 第一个画面更像可停留的广场，而非摆放模型。 |
| P0 | 六地点的剪影与动态动作 | 为每地点建立一个低成本循环动画并在完成后改变颜色、灯或形体。 | 不读文字也知道哪里“有事”、哪里已改变。 |
| P0 | Pi 同伴与出发路径表演 | 眼神、呼吸、光晕、提包、暖色路径灯与镜头推进。 | 玩家感到 Pi 是主动调查的伙伴，而不是 UI 中的状态。 |
| P1 | 暮色光照与港口气氛 | 低位主光、冷暖色对比、雾、暖窗、灯、烟、船、萤光。 | 场景获得时间感和情绪，而非平光模型预览。 |
| P1 | 地点旁的微型叙事道具簇 | 程序摆放但对关键画面做手工位置微调。 | 城市有生活痕迹，且每个地点更容易被记住。 |
| P2 | 轻量状态镜头与无 UI 截图模式 | 为计划、远征、回流和完成给出不同距离/角度，支持后续截图比较。 | 让“结果改变下一步”在画面节奏中成立。 |

## 不应采用的方向

本轮不将生成概念图直接贴为背景，也不以照片级纹理、海量粒子、过多 GLB 或可自由驾驶的角色来伪造精致度。它们会让教学故事变成风景展示或生产规模失控。目标是**少而有意义的实时表演**，使每处动态和每一件道具都服务“看见、提出未知、Pi 自主调查、带回结果、城市改变”的循环。
