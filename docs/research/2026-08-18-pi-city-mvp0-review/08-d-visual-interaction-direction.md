# Pi City D 灰盒：视觉与交互重构方向

## 为什么现有灰盒不对

当前喷泉灰盒完成了状态机验证，但它从旧 Pi City 继承了工业港口、深色控制台、四象限信息桌、状态标签和硬边框卡片。这套语言适合解释一段已发生的 Agent Runtime，却不适合非技术玩家与 Pi 一起探索一个尚未弄清的城市小问题。

它产生了三个错位。第一，玩家面对的是“仪表盘”，而不是一个正在发生的故事；第二，Pi 像状态机的消息来源，而不是会观察、犹豫、出发和改变想法的伙伴；第三，问题卡像实验面板中的选项，削弱了“我发现还有一件事没想清”的自然感。

新主线不应把 Pi City 做成更温暖的 Dashboard。它应该像一场**可触摸的城市小冒险**：玩家和 Pi 在一个会回应调查的微缩街区里，把看到的碎片、未解的疑问和新带回的发现慢慢串起来。

> **新体验承诺：不是“管理 Pi 的运行”，而是“和 Pi 一起把城市里的一件小事弄明白”。**

## 新的视觉世界：夜航小城与调查手账

视觉不再以黑绿工业港口为默认基调。喷泉任务应采用 **温暖暮蓝、奶油纸色、珊瑚橘和水波青** 的小城夜景：像一本被翻开的互动图画书，也像桌上可走进去的手工微缩模型。世界有夜风、喷泉、水滴、乐谱碎片、纸船和街灯；但不过分使用“cozy”符号，也不采用儿童化的糖果色。

Pi 的身份从“系统状态”转为一个小小的、带着发光口袋的调查伙伴。它的行动通过可读的身体语言表现：侧耳倾听、把发现放进随身口袋、沿着纸带/水流前进、把物件摊到手账上。玩家不会看到 Pi 的内部控制台，只会看见它如何把一个问题带到城市中去。

| 旧语言 | 新语言 |
|---|---|
| 工业港口与计算中心 | 暮色小街、码头、喷泉与可进入的微缩城市。 |
| 四格 Dashboard | 一张贯穿场景的调查手账；信息按故事时间出现。 |
| 数据卡、状态编号、长标签 | 物件、便签、光点、水波、纸带与短句。 |
| “AUTHOR-DEFINED · NOT A TRACE” 顶栏提示 | 低调的“故事模式”书签；点击后才说明“这是教学故事，不是一段真实运行”。 |
| 高光按钮和硬边框 | 在世界物件上出现的柔和可点击光晕；每次只有一个焦点。 |
| Pi 的文字状态 | Pi 的小动作、简短对话和可见行动理由。 |

## 新的交互语法

### 1. 场景先于桌面

进入任务后，玩家首先看见的是喷泉、乐手、Pi 和“第七拍突然变小”的现象。不要先出现任务面板。Pi 自己完成第一次初看，玩家只需点一次“靠近看看”，让世界产生第一个可触摸的异常。

### 2. 未知问题长在世界里

当 Pi 带回“第七拍水压下降”时，不展示纵向问题卡列表。将三个待解方向化为场景中的三个轻量“疑问种子”：

| 待解方向 | 世界化呈现 | 玩家读到的意思 |
|---|---|---|
| 缺少旋律 | 飘在乐手音符附近的断拍纸带。 | “是不是还缺旋律的信息？” |
| 水压因果 | 浮在喷泉水线上的一枚小水滴记号。 | “水压下降是原因，还是巧合？” |
| 风的影响 | 港口风铃旁一条轻轻晃动的风线。 | “风会不会吹断了声音？” |

玩家点的是一个“想继续问的现象”，而不是界面上的标准答案。悬停或点选时，Pi 才用一句自然语言把问题说完整。

### 3. Pi 的计划是一段可跟随的小旅程

玩家选中未知后，Pi 不应该弹出一张命令确认卡。Pi 在手账边缘画出一条细短路线，用一句话解释：“那我去问问码头乐手。”玩家唯一的节奏输入是“跟上 Pi”。随后镜头/背景轻微滑向目的地，Pi 的口袋带回一个新物件。

### 4. 结果不是进入第四格，而是改变手账

任务底部有一条小小的调查手账：物件按先后落在纸带上，新的发现会用一根细线连接到它回答或否定的疑问。反证不显示失败色；它会让原先的风线淡下去，变成一句“不是风”，同时让 Pi 说“那我们把注意力放回水和歌上”。

玩家看到的是“共同笔记变清楚了”，而不是“系统状态从 5 变成 6”。

### 5. 确认是城市里的庆祝，而不是结算步骤

同步阀装好后，玩家看到喷泉短暂试唱。Pi 转头问：“怎样才算真的办好了？”完成条件仍然是一个来自世界的可点击现象：晚风中的完整旋律，或工具坊稳定的水线。晚风试演完成后，乐手、喷泉、风铃和纸船共同组成结局；只在结束后的可选书签里揭示“这帮助你理解 Pi 的哪种思考”。

## 交互层级

| 层级 | 屏幕中保留什么 | 屏幕中不再出现什么 |
|---|---|---|
| 常驻 | 场景、Pi、当前居民、调查手账、一个低调故事书签。 | 顶部产品标语、技术状态、四区表格、长任务说明。 |
| 当前焦点 | 一个可点击世界线索或一个 Pi 行动。 | 同时出现 3 个以上同权按钮。 |
| Pi 的解释 | 1 句行动理由，至多 15 个汉字。 | 工具名、Context、验证等术语。 |
| 结果回流 | 物件变化、手账连线、1 句“知道了什么”。 | “正确/错误”、分数、进度经济。 |
| 真实性说明 | “故事模式”书签中的简短说明与可选 Trace 翻面。 | 让教学故事伪装为真实 Trace 的任何界面语言。 |

## 研发中的最小重构范围

本轮不重做现有 Evidence Explorer、真实 Trace 回放或工业港口的历史视觉资产。它们仍服务“观察真实运行”的产品线。本轮只重构 **教学故事模式的喷泉灰盒**，让它成为 Pi City 新游戏主线的第一个可信片段。

实现应包含：一个温暖的全屏故事场景；左/右或前/后有节奏的角色与世界层；可点击的三类调查线索；底部调查手账；Pi 行动时的短暂场景切换；反证与新事实的手账动画/状态；低调故事模式标签和可选教学翻面。它不需要新的 3D 引擎、完整角色动画或正式美术资产。

## 第一轮验收问题

1. 玩家在前三十秒看到的是“一个城市小问题”，还是“一套 Agent 面板”？
2. 玩家能否说出“我想弄清风，所以 Pi 去港口”，而不是“我按了第三张卡”？
3. 玩家是否能从手账变化看懂“不是风”为什么仍然有价值？
4. Pi 是否看起来像会行动、会带回东西、会改变想法的伙伴？
5. 玩家是否会想看看下一个城市委托，而不是立刻找技术解释？

若这些问题的答案仍然是否定的，不应继续增强装饰、动画或旧 Dashboard，而应再审视“从世界中提出未知”的交互本身。
