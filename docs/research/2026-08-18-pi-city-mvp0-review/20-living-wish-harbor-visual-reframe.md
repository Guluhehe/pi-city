# Pi City「会呼吸的心愿港」视觉重构方案

## 结论

当前版本已经是一个**可玩的、温暖的故事城市**；它还不像一个令人想立刻走进去的游戏场景。核心问题不在模型面数或调色精度，而在于首屏的注意力被标题、三张卡、喷泉、灯串、信任图和建筑同时分走。玩家看到的是“一个内容很多、运作良好的港口”，而不是“有一件神秘又温柔的事情正在发生，我必须和 Pi 靠近它”。

> 这次重构的目标不是把 Pi City 做成更炫的技术展示，而是让它在前五秒形成一个清楚的情绪承诺：**这座港会回应每一件小心愿；Pi 和我能让它变得不一样。**

## 新的视觉北极星：会呼吸的心愿港

把喷泉从静态广场中心升级为**心愿潮汐**。它不是一个普通喷泉，而是一团漂浮在水面与天空之间的、由纸船、灯种、碎星和居民物件组成的温柔涡流。当前可办心愿会从涡流里浮出一个独特的“未完成征兆”；Pi 站在画面近处，面向征兆。玩家的第一眼先看到**城市正在求助**，第二眼看到**Pi 在等我决定**，第三眼才读取标题与按钮。

| 画面层级 | 画面应该承担的问题 | 具体设计 |
|---|---|---|
| **主导层：一个会变化的心愿奇观** | “这里正在发生什么？” | 每章仅有一个大而清晰的动态征兆：章节一是回旋而熄灭的灯塔微光；章节二是被风卷起又落下的纸风筝/档案页；章节三是未开花的发光种子与慢转风车；章节四是尚未连成线的星灯。 |
| **次焦点：Pi 与带回物** | “我和谁一起做？” | Pi 固定在前景三分线，形成清楚轮廓：小灯帽、背包、两只深色眼睛、带回物的彩色边光。归来时，不是再制造一团白光，而是带着可辨认物件跑入奇观，令奇观出现一次可见回应。 |
| **背景层：会等人的港口** | “这是什么地方？” | 建筑退成冷色剪影；少数窗口、船屋、烘焙店/档案门有暖光。远处天空、海面和灯塔保留大块留白，作为奇观与下一处地点的舞台。 |

这套三层结构遵循“只让一个元素主导、少量元素成为次焦点”的层级原则，而不是继续增加同样亮的物件。[1] 温馨感也来自“被保护的暖处”与港外天气/海面之间的对比，而不是全画面平均加暖加亮。[2]

## 首屏：从“信息页”改为“抵达一件正在发生的事”

首屏应分成三拍，而非一次把所有内容展示给玩家。

| 时间 | 玩家看见的内容 | 交互与镜头 |
|---|---|---|
| **0–2 秒：港口先呼吸** | UI 几乎不出现。镜头从一盏近景路灯/一页纸船后轻推到心愿潮汐，Pi 在前景抬头。海面、风、纸船和灯火先建立气氛。 | 轻微推镜、近处遮挡、远处大留白；不显示三张任务卡。 |
| **2–5 秒：当前心愿显形** | 仅出现一句居民的低声请求和一个可点击的奇观/物件，例如“风筝又被风卷走了”。 | 玩家点击奇观或 Pi，才打开一张“和 Pi 一起去”的单卡。 |
| **5 秒以后：玩家主动阅读城市** | 信任图、发现册与章节任务卡从边缘/码头公告板中自然展开。 | 信息变为玩家主动打开的城市记忆，而非压在世界上的常驻面板。 |

这样做并不是隐藏系统，而是先让空间回答“我在哪里、这里发生了什么、我能做什么”。环境叙事研究强调，空间应在最初时刻让玩家理解自己的关系与下一步，并用可见因果提示把人往前拉。[3]

## 每章不换一套城市，而是换一件“城市正在回应的事”

现有 `ChapterLandmark` 可以升级为 `WishPhenomenon`：仍使用低成本 Three.js 程序几何、GLB 地标和粒子，不需要重做全城。

| 章节 | 当前主要识别 | 升级后的章节奇观 | 城市完成反馈 |
|---|---|---|---|
| 第1章：先看、带回、确认 | 灯塔、邮局、喷泉 | **回信灯潮**：熄亮不稳的纸灯沿水面打转；确认后灯潮稳定地通向灯塔。 | 灯塔光束真正扫过屋顶，纸船在水面排成回信路线。 |
| 第2章：记得，也重新想 | 风筝、钥匙、电影 | **记忆风**：风筝尾、旧地图页、钥匙拓印在风里排列又重新组合。 | 风筝绳在屋顶拉出一条线，档案门透光，雨棚像一张温柔的大伞展开。 |
| 第3章：动手，也收尾 | 种子、感谢卡、风车 | **成长花圃**：未开的夜花轻微收缩，卡片随风翻面，风车影子断续掠过地面。 | 夜花成片点亮；卡片墙成为新的暖光来源；风车叶在远景缓慢稳定地转。 |
| 第4章：更多人相信 Pi | 双心愿、雾铃、星光节 | **城市合唱**：两股不同颜色的灯流暂不相接；雾中远铃闪烁；星光还差最后一段。 | 两股灯流连成网，雾灯照海，最终星灯从港口向天空逐层亮起。 |

关键是这些变化必须是**因果反馈**，不是单独播放的庆祝特效：玩家带回的事实让世界以不同方式组织自己。这样玩家重返码头时会一眼看出“是我和 Pi 让这里变了”。

## Pi：从小型移动点，变成城市的情绪引擎

Pi 现在功能正确但轮廓偏弱。建议不改变其温和气质，只强化可读性。

| 维度 | 当前问题 | 改造方法 |
|---|---|---|
| 轮廓 | 远景易被石板、喷泉和灯串吞没。 | 固定“灯帽 + 圆头 + 小背包 + 两点眼睛”的剪影；使用更深的下半身色和一圈低强度薄荷色边缘光。 |
| 站位 | 多数时间位于空间中段，像场景中的一个小物。 | 首屏与关键选择时置于前景 1/3 位置，交互物在其视线方向；镜头低于/平于 Pi 的视线，而非长期俯瞰。 |
| 动作 | 漂浮与光效表达“正在动”，但未表达“正在思考”。 | 增加三套简短、可复用姿态：侧头看征兆、从小包取出带回物、把物件放入心愿潮汐。 |
| 关系 | 玩家像在点菜单，Pi 像在执行。 | 每次出现新问题，Pi 先看向一个城市物，再回头看玩家；用视线、停顿和一个小动作询问，而非只弹出气泡。 |

## 交互与界面：减少覆盖，增加“在世界里找到”

现有卡片信息正确，不需要推倒；应该改变其出现时机与空间归属。

| 保留 | 改造 |
|---|---|
| 办事手账、小包、发现册、信任图和可读的选择理由 | 首屏不常驻展示三张大心愿卡；改为一个“今日心愿”小卡和港口中的 2–3 个可见征兆。 |
| 右侧地点选择卡的解释能力 | 选择前，先让相应地点在3D中发生一次 0.6 秒的回应：风铃轻响、屋顶掠过线影、图书馆窗透出纸页光。卡片随后出现，成为确认而非替代空间。 |
| 底部手账的证据功能 | 在没有带回物时缩成一张纸签；带回第一件物时才像桌面一样展开。电影小包保持在手账中，但第一次填格时做一次短促的物件落入动画。 |
| 信任图的章节进度 | 从右侧面板转成码头背景中的一面“心愿航图”或悬挂灯串；点击才拉近成为详细UI。 |

## 最小可验证原型：先做“第2章记忆风”

不要从重做12件任务或替换所有建筑开始。先在第二章做一个 20–30 秒的可玩视觉切片，因为它同时包含风筝、档案页、两格小包和雨棚四种可见变化。

### 原型范围

| 必做内容 | 目的 | 现有基础设施复用 |
|---|---|---|
| 低机位抵达镜头 + 近景遮挡 | 把港口从俯瞰模型展示变为可进入的地方。 | `FountainCamera`、已有路线时间。 |
| `WishPhenomenon`：风筝尾、纸页、两色风流 | 建立前五秒唯一视觉主角。 | `ChapterLandmark`、`useFrame`、路线灯。 |
| Pi 的三种姿态与低强度轮廓 | 让 Pi 成为情绪主角。 | `PiCompanion` 与已有背包/带回物。 |
| 第一张心愿的世界内提示 | 验证“先看奇观、后看卡片”是否更有探索感。 | `CityStoryHub`、可延迟显示的UI状态。 |
| 完成后的屋顶风筝绳和档案门暖光 | 验证城市改变能否被一眼感知。 | 现有 `ChapterLandmark` 完成状态。 |

### 通过标准

在不读标题的静帧里，玩家应能回答三件事：**这里有一件不对劲的事；Pi 正在关注它；我靠近后会帮助这座港改变。** 如果截图仍然首先像“有很多卡的3D网页”，就不算通过。

## 不建议的做法

不要用更多随机小房子、更多飘粒、全面加强 bloom、统一加饱和或把每张任务卡做得更华丽来解决问题。这些会增加密度，却不会创建主角和情绪方向；还会进一步损害当前温柔、低压的气质。应先重排注意力与因果，再补材质、纹理、音效和局部高精模型。
