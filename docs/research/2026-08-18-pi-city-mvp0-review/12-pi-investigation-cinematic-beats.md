# Pi 调查往返短表演：近景镜头与可见发现

## 目标

将现有的 `plan → expedition → return` 状态转换从“文字卡片换页”转化为一段约六秒、无需额外规则的城市小冒险。表演完全是展示层：它不改变喷泉状态机、不写入 Semantic Trace，也不取代玩家提出未知问题和确认 Pi 计划的动作。

> **表演句法：** 玩家提出一个未知问题，Pi 在喷泉边接住问题；玩家确认跟上后，Pi 沿着被点亮的路线前往地点；Pi 带着有形的发现回到喷泉，城市和手账随后解释它的意义。

## 三段时序

| 既有状态 | 屏幕表演 | 镜头 | Pi 与城市的动态 | 玩家关系 |
| --- | --- | --- | --- | --- |
| `plan` | Pi 接住问题，准备出发。 | 镜头从广场轻推到喷泉与 Pi 的近中景；目标地点留在侧后方作为“要去哪里”的承诺。 | Pi 在喷泉旁停住、光晕收束；路线灯开始依次亮起。 | 玩家阅读 Pi 的计划并点击“跟上 Pi”。 |
| `expedition` | Pi 沿路线前往地点。 | 相机以偏高的跟拍角度沿 Pi 与路线移动；保持目的地剪影在画面中。 | Pi 在约 2.7 秒从喷泉移动到目标，路线灯形成向前推进的暖色波。UI 自动等待该短表演结束。 | 玩家已经确认计划，因此只观看 Pi 的自主行动；不要求连续操控。 |
| `return` | Pi 拎着发现回到喷泉。 | 相机沿反向路线回移，并在喷泉处收束到带回物与水柱的同框。 | Pi 的提包出现一个随发现类型变色的发光小物；回程路线以反方向波动；事实对应地点立即发生可见变化。 | 玩家在 Pi 回来后阅读“带回来的东西”，再决定记入手账。 |

## 实时实现边界

| 部分 | 实现方案 | 不做什么 |
| --- | --- | --- |
| 状态时钟 | 在 `FountainStoryScene` 的呈现组件中按阶段重置本地秒表。 | 不把计时、镜头、动画像事实写入 reducer 或 Trace。 |
| 相机 | 使用现有 R3F `useFrame` 对焦点与跟拍位做缓动；镜头仍以广场为基线。 | 不引入可眩晕的自由相机、过场视频或切黑。 |
| Pi 移动 | 由喷泉至目标、再由目标返回喷泉的缓动位置；移动朝向跟随路径。 | 不引入寻路、碰撞、可控角色或额外地图系统。 |
| 带回物 | 小型实时网格（纸页、水滴、银风铃或暖色试演火花），依据 `lastReturn.kind` 改色。 | 不使用静态概念图、全屏粒子特效或难以读懂的技术符号。 |
| UI 节奏 | `expedition` 卡片延迟约 2.7 秒后才转换到 `return`，给短表演留出可见时间。 | 不增加新的玩法按钮或违反现有状态机合法顺序。 |

## 验收准则

当截图分别落在 `plan`、`expedition`、`return` 时，观察者即使不读任何技术术语也应能辨认：**Pi 正在考虑、Pi 正在去某处、Pi 带着一个东西回来了。** 这三张画面分别保留喷泉、目标剪影和发光发现至少两个可见叙事锚点。


## 可复现录制

使用 `node scripts/record_fountain_cinematic_demo.mjs` 可从真实页面依次触发：进入喷泉街、初看、选择“去码头乐手看看”、近景计划、Pi 出发、Pi 带回发现、记入手账。脚本通过 Playwright 的 Chromium 视频录制功能捕获实际 R3F/WebGL 画面，并保存计划近景、目的地到达与回程三个阶段截图。

本轮交付的最终动态演示为 1280×720、25 fps、约 64 秒的 MP4，同时提供 640 px 宽 GIF 预览。它是浏览器中实际状态机和实时3D动画的录制，不是由静态图拼接或由生成模型合成。
