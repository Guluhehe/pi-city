# Pi 英雄资产风险原型：评估与决策

## 结论

**不建议把当前程序化英雄Pi原型合入正式游戏。** 它证明了正确方向——短腿、提灯帽、手臂、双肩包、深青主体和暖眼睛的确比原来的单球更接近“随身助理”——但实拍结果仍然是“由基础体块拼出的角色”，与目标图中的一体化轮廓、材质触感、比例控制和近景表演相差很远。继续在这组球体、圆柱和方盒上堆零件的边际收益很低，会把临时灰盒误包装成最终美术。

这是一项有价值的失败：它把问题从主观的“感觉变味”变成了可验证的制作判断——**当前缺的是英雄角色资产和镜头前环境资产，不是新特效或新渲染引擎。**

| 判断问题 | 结论 | 证据与影响 |
|---|---|---|
| Three.js/R3F 是否是主要问题 | 否。 | 当前已有GLTF、PBR、阴影、ACES、雾和后期；本轮原型也能在同一管线中渲染角色层级。更换引擎不会自动增加角色剪影、贴图或材质质量。 |
| 程序化基础体块能否承担最终Pi | 否。 | `hero-pi-memory-wind.png` 中新增帽子/短腿/背包已能传达身份，但轮廓仍碎片化，贴图/接缝/受光不具备概念图的完整性。 |
| 当前Pi模型需要什么 | 专门的低多边形英雄GLB。 | 它至少需要统一轮廓、4–6个材质分区、可见背包结构、可观察的手臂、骨架和3个短动作。 |
| 全城是否需要立即重做 | 否。 | 先完成“记忆风街角 + 英雄Pi”这一可玩的近景切片。它通过后，再将材质规则推广到12项委托。 |
| 是否应继续增加Bloom/光球 | 否。 | 这会放大当前几何与材质不足，不能形成目标图的湿石、木材、布料与局部暖光层次。 |

## 原型的正面收获

本轮生成的 `pi-assistant-hero-reference.png` 锁定了值得保留的身份锚点：深青主体、铜色提灯帽、暖黄眼、棕色双肩包、短腿、可伸出的手臂和纸页收纳。`memory-wind-street-kit-reference.png` 进一步锁定了环境策略：前景大灯/绳索、湿石板、深色木屋、红门台阶、暖窗和由暗到亮的记忆风。它们可作为正式资产制作的参考，不应直接代替可交互3D。

原型代码同样具有保留价值：`heroPi` 是一个仅在 `?artPrototype=memory-wind` 下开启的隔离路径，证明角色资产可以接入现有Pi移动、带回发现和镜头逻辑，而无需推倒任务状态机。

## 推荐的正式资产规格

| 资产 | 最小正式规格 | 验收条件 |
|---|---|---|
| Pi 英雄GLB | 约3k–8k三角面；独立的身体、帽灯、双肩包、脚和手臂网格；身体/皮革/铜/灯玻璃/纸页五类材质；一套简单骨架。 | 黑色剪影下能辨识“提灯帽 + 双肩包 + 短腿”；在当前近景镜头中眼睛、背包、手臂三者同时清楚。 |
| Pi 动画 | `idle-observe`、`take-note`、`turn-and-trot` 三段各0.8–1.4秒，可循环/衔接。 | 分别承载“看见、带回、改路”；不再仅靠漂浮和发光表达动作。 |
| 记忆风街角套件 | 红门窄屋、两种坡屋顶、木窗、石台阶、湿石板、灯柱、绳索、船和风筝骨架。 | 在关闭奇观时仍然像可居住的港口；开启时让红门成为远方目的地。 |
| 材质包 | 深木、潮湿石、磨砂青漆、棕色皮革、铜/玻璃、红布、旧纸；每种都含基础色/粗糙度/法线或手绘替代。 | 在蓝夜+暖灯+奇观三种光线下不泛白、不塑料、不丢失层次。 |

## 工程路线和实际代价

现有项目可以直接加载一个带贴图的GLB，因此正式路线是保留Three.js/R3F、替换Pi组件为专门GLB、制作一小组模块化近景环境网格，并在现有灯光/相机中进行校准。浏览器性能上，单个3k–8k三角面英雄角色和一个小街角套件并非高风险；真正的工作量来自角色建模、UV、材质、骨架、动画和持续的概念对照审核。

本环境没有内置的“图像直接变成可用、可动画GLB”能力。要获得接近参考图的正式角色，建议在下面两条路径中选一条：

1. **外部DCC/角色资产路径（推荐）**：在Blender等工具中制作或委托一份符合上表规格的Pi GLB；再导入当前项目。它风险最低，质量上限最高。
2. **外部3D生成服务路径**：若用户提供可用的3D生成服务密钥，可先生成基础GLB，再在Blender中清理UV、材质和骨架。该路线仍需人工修整，不能把单张概念图直接当成最终资产。

在正式GLB到位之前，应该把 `heroPi` 保留为开发参考而非默认画面。其价值是验证接入点，绝不是最终角色质量。

## 下一步建议

先由用户确认“以正式Pi GLB + 记忆风街角套件”为下一个美术生产里程碑。确认后，我会把已生成的角色和环境参考整理为资产简报，落实可导入GLB的网格、材质、骨架和动画验收表；拿到角色资产后，再完成一个真正可玩的三镜头切片，而不是继续给当前低模场景做表面修补。
