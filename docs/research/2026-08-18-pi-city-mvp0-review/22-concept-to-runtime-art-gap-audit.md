# Pi City 概念图与实时3D实装的风格断裂审计

**结论先行：问题以资产与美术落地为主，而不是 Three.js / React Three Fiber 的技术选型错误。** 当前运行时已经具备 ACES 色调映射、阴影、雾、GLTF 加载和后期合成的基础能力；但它把这些能力用于了“低模功能地标的拼接”，没有形成概念图所要求的角色主导、电影化构图和有材质层次的港口。继续增加光球、发光与卡片，只会让这个差异更明显。

## 1. 两种画面语言的根本差异

| 维度 | 目标概念图 | 当前实时实装 | 对体验的影响 |
|---|---|---|---|
| 叙事主角 | 左下角的 Pi 有明确剪影：圆润身体、短腿、提灯帽、背包、面部灯眼；它站在玩家可以代入的观察位置。 | Pi 是由球体、两枚小眼和方形小包组成的功能性标记，常被喷泉、地标或界面遮住。 | Pi 看起来像场景特效或地图图钉，而非可以一起办事的助理伙伴。 |
| 构图 | 前景虚化灯笼和绳索 → Pi → 记忆风奇观 → 港口建筑和夜空，形成四层景深与明确视线路径。 | 平视广场 + 均匀分布的房屋/地标 + 居中喷泉；同一画面里的对象重要性相近。 | 玩家没有“先看哪里、为什么靠近”的视觉答案。 |
| 建模 | 建筑有屋檐、坡面、窗框、台阶、船只、绳索与不规则比例；形体以轮廓和层次取胜。 | 远景 `HarborHomes`、船和许多任务物仍由标准盒体、圆柱、球体直接构成；现有GLB地标尺寸仅约24–128 KB，不适合作为近景英雄资产。 | 画面读起来像灰盒或教育演示，而不是能停留观看的游戏城镇。 |
| 材质 | 深色木、潮湿石板、磨砂金属、发光窗、粗布风筝和旧纸共同提供粗糙度、反射和色温差异。 | 大部分网格使用单色 `MeshStandardMaterial`，缺少贴图、法线、倒角、顶点色和材质分区。 | 体块正确但表面没有生活痕迹，无法建立温度与尺度。 |
| 光照与氛围 | 深蓝夜色作为大面积暗部；少量暖灯、月亮、窗口和奇观成为精准高光；前/中/后景有雾化分离。 | 天空与环境光较亮，暖光较平均；喷泉与发光物容易成为大面积亮块。 | 缺少暗部保护和选择性注意力，奇观也因此不够珍贵。 |
| 动态 | 风筝尾、纸页、光点、远处船和Pi处于同一个镜头叙事里，动态服务于一个问题。 | 动态多为孤立的旋转、跳动、路径光点和发光；各自正确但没有共同的镜头句子。 | “有动画”不等于“有表演”。 |

## 2. 当前技术并非瓶颈

`FountainStoryScene.tsx` 已经使用 `GLTFLoader`、阴影、`ACESFilmicToneMapping`、sRGB 输出、雾、`EffectComposer` 和 `UnrealBloomPass`。这足以完成风格化的中等规格浏览器3D场景；直接更换引擎会失去既有状态机、镜头、任务和资产管线，却不会自动获得更好的美术。

真正的缺口在于**英雄资产策略**：现有 GLB 只适合远景轮廓，程序化标准几何只适合灰盒验证。下一阶段必须把视觉预算集中到一个有身份的 Pi、一个可近看的港口街角套件，以及一组能统一表面的材质/贴图，而不是平均升级整个12任务城市。

## 3. 必须做出的改造决策

| 决策 | 结论 | 理由 |
|---|---|---|
| 是否更换Three.js/R3F | **否。** | 现有渲染与交互能力足以承载目标；重写风险远高于收益。 |
| 是否继续仅靠程序化基础体块 | **否。** | 可以保留作远景和碰撞体，但不能再承担Pi、镜头前建筑或关键任务物。 |
| 是否马上重做全城模型 | **否。** | 先用“记忆风街角”证明资产和材质管线，再扩展至其他章节。 |
| Pi是否应成为独立角色资产 | **是，优先级最高。** | Pi 是玩家的情感入口，必须能在缩略图、近景、侧背面和行动中被一眼认出。 |
| 是否采用电影化光照规则 | **是。** | 每个镜头只允许一组主暖光和一处叙事奇观高光；天空、建筑和地面负责暗部与层次。 |
| 是否用概念图直接替代实时3D | **否。** | 概念图用于约束视觉目标；实际游戏需要可交互的实时资产与状态反馈。 |

## 4. 最小可行美术重构：一条“记忆风街角”而非一个全城

第一条可验证路径是把第二章的镜头前区域改为一个可近看的港口街角：潮湿石板、两座有窗框与坡屋顶的窄房、红门台阶、前景灯柱和一艘远处小船。Pi 使用独立的低面数风格化角色模型：深蓝磨砂主体、短腿、暖黄眼、铜色小提灯帽、棕色双肩小包、可见的纸页收纳槽。记忆风则用曲线条带、双面纸片、暖色光点和一个红色风筝骨架实现，而非多个离散的几何体特效。

这条风险原型要先满足三项截图判定：一是遮住文字仍能在一秒内认出Pi；二是把画面缩至手机宽度，仍能看出前景Pi、中央奇观和远处红门的三层关系；三是关闭奇观时，街角仍像一个可居住的夜间港口而不是任务场地。

## 5. 资产与工程路线

我们不需要把AI概念图转成不可控的整城3D模型。正确路径是先生成 **Pi 正面/侧面/背面角色设定与材质小样**、**记忆风街角材质板**、**红门/窗框/石板/木材四组可平铺贴图**。以该资产板为约束，在现有Three场景中搭建少量带倒角的手工网格，或导入一个专门制作的低多边形 GLB Pi。Pi的最终可动模型需要独立网格、骨架和三个短动画（观察、取页、转身/小跑）；若要高质量自动化GLB生成，则需要用户提供对应的3D生成服务密钥或在外部DCC工具中制作。此前的一张概念图只能作为方向，不应假装已经是可用模型。

## 6. 建议的下一步风险原型

在不触动其余11个任务的前提下，制作一个 `?artPrototype=memory-wind` 模式：只渲染更新后的Pi、记忆风街角、电影灯光和现有任务UI。先以生成的角色三视图与材质小样校准风格，然后将Pi的“观察—挑页—改路”接到当前状态机。若截图达到三项判定，再把这套资产/材质包推广至全城；若失败，则在全城重构前先替换英雄Pi模型与镜头前街角资产。

> **需要正视的代价**：角色资产和近景环境不是在现有低模组件上改几行参数就能获得的。它们需要新的可复用网格、材质、动画，以及把UI从镜头主角降为辅助层。这是一次小范围但真实的美术制作，而不是后期滤镜工作。

## 7. 研究支撑

风格化角色的生产关键不在于把几何体加得更复杂，而在于先锁定形体语言、纯剪影可读性、价值层级和英雄资产标准；这些正是当前Pi从“功能球体”变为“可代入助理伙伴”所缺失的环节。[1] 该资料亦将“风格化PBR”描述为兼顾可控美术限制与引擎友好性的可扩展路线，因此适合作为Pi City而非全量NPR重写的选择。[1]

实时风格化环境的常见制作顺序也是先锁定概念对应的相机与大形体，再用倒角、可平铺贴图/trim sheet、材质混合和少量聚焦灯光逐层增加可信度；它直接对应本项目“记忆风街角优先、全城后置”的资产策略。[2] Three.js现有的线性色彩管理与GLTF加载支持可避免PBR贴图和灯光因Gamma处理错误而产生泛白或塑料感；后续材质包应按该工作流验证，而不是继续以任意十六进制颜色与发光强度试错。[3]
