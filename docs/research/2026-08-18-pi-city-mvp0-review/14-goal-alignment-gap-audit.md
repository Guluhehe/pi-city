# Pi City 目标对齐与体验缺口审计

## 审计结论

当前喷泉街已经不再是“技术网站上的一段说明”。它拥有实时 3D 小镇、多地点热点、Pi 的自主往返、反证路线、工具坊解锁、最终确认，以及故事与 Semantic Trace 的独立状态边界。最近完成的故事优先首镜头也把玩家第一次看见的内容从旧技术菜单换成了喷泉街。

但它仍然更接近一个**制作精良的单任务演示**，而不是原始设计所承诺的“会被帮助、被记住、逐渐变亮的城市冒险”。最危险的缺口并非材质或模型精度，而是：**玩家的选择理由、世界对选择的回应、可选发现与长期城市记忆尚没有形成闭环。** 如果继续只加镜头、灯光和场景道具，会让作品更像漂亮的展示，而不是更像游戏。

> 原始北极星不是“让用户看懂 Agent 面板”，而是让非技术玩家自然说出：**Pi 会先去看看；做完后会把新发现带回来再想；确认真的好了才会告诉你。** [1]

## 当前体验的四个核心断裂

### 1. “选什么”还没有从城市中长出来

D 机制最重要的不是让玩家在三个题目中点击一个，而是让玩家提出一个自己觉得值得弄清的未知。当前提示卡已经使用自然语言，但世界中的乐谱、浮标与风铃更多是精美地点，尚未成为促成判断的**可读证据**。这会让 H2 的失败信号——“因为它亮了／游戏让我点”——仍然成立。[2]

首要修复不是增加问题数量，而是为三个地点各增加一个在选择前就可见的“一眼证据”：乐手码头的第七拍空白乐谱、水线小渠在第七拍下沉的浮标刻度、风铃巷中与断拍不一致的飘带节奏；同时让 Pi 用一句不带答案的观察邀请玩家判断。这使问题的文字成为玩家已经看见的现象的命名，而非按钮标签。

### 2. “带回来再想”还缺少一场看得懂的仪式

当前 Pi 的回程、发光带回物、底部手账和工具坊解锁分散在几个屏幕区域。它们都在，但玩家可能没有把它们读成同一个因果。原始设计要求发现物回到思考塔，放在一起后再改变路线；Story→Trace 契约也将此定义为首个翻面的唯一时刻。[3]

应在喷泉边增加一个极简的**思考桌/回响台**：每次回程，发现物先落到桌面格位；第二件关键发现抵达时，两件物件之间亮出一条可理解的连接，Pi 说“把这两件事放在一起看看”，工具坊远处再点亮。它只使用现有事实和场景网格，不增加新的流程按钮，却把 H1/H3 的核心因果集中到一个视觉动作。

### 3. 世界变化存在，但居民没有“记住”玩家

当前环境会亮、变色、加飘带，但委托人的情绪、感谢和后续生活很弱。原始设计将城市变化定义为情感进度，不是特效进度；玩家应看到“我帮这个城市带来了什么”。[1] 当前乐手是动态模型，却没有在完成后演奏完整旋律、转向 Pi、或留下可以回看的回应。

第一轮不需要实现信任图或十二个任务。只需让喷泉任务在完成后完成三件小事：乐手奏出完整回应，风铃与水声同步，广场出现一封/一只感谢纸船；再次进入时，居民的第一句台词也由困惑变为“那首歌还在唱”。这会把城市状态从“GPU 效果”变成“居民生活的后果”。

### 4. 可选发现、深度翻面与长期回访仍是空层

玩家声音研究明确指出，短局只有在每局保留个人发现与不同后果时才不会沦为一次性直线消费。[4] 当前喷泉任务的风铃反证虽是有价值的温和绕路，但缺少一件能带走、回看或影响角色关系的小发现；故事结束后也没有可选的 Pi 小知识或兼容 Trace 翻面。因此既缺少“我还想看看”，也缺少“我想知道 Pi 在现实里如何再想”。

应将风铃路线奖励为一枚 **“不随风断拍”小铃片**，进入发现册；完成同步阀后在不打断结局的前提下显示一张折叠的 **Pi 小知识** 卡：先复述故事因果，再邀请“看看另一个真实 Pi 示例”。若暂时没有兼容 Trace，则诚实显示档案馆待开放。这样同时服务重玩、H5 真实性和技术深潜，而不强迫任何人读日志。

## 优先级与精修范围

| 批次 | 目标 | 本次应做的最小垂直切片 | 明确不做 |
| --- | --- | --- | --- |
| **P0-A：选择可读性** | 让玩家在点热点前就能说出理由。 | 三地点预选择证据、Pi 的无答案观察、选择后保留“你是因为看见什么而去”的小句。 | 新地图、自由移动、复杂谜题。 |
| **P0-B：回流仪式** | 让两件发现导致新计划成为画面中心。 | 喷泉旁思考桌、物件回位、双发现连接、工具坊远处点亮。 | 额外的状态机或技术术语教学。 |
| **P0-C：居民与可选发现** | 将反证变为有收获的城市故事。 | 风铃小铃片、乐手完成回应、感谢纸船、可回看发现卡。 | 收藏货币、稀有度、评分或成就刷取。 |
| **P0-D：自愿翻面** | 让故事与真实 Pi 相互照亮。 | 折叠 Pi 小知识卡、明确“作者定义教学故事”、无兼容 Trace 时的诚实空状态。 | 把完整 Explorer 嵌入任务或伪造匹配证据。 |
| P1：可扩展任务语法 | 防止喷泉成为孤立 Demo。 | 定义下一个“灯塔确认”任务复用的状态与资产契约。 | 同时制作三到十二个任务。 |
| P1：长期城市记忆 | 把单局结果变成可回访痕迹。 | 本地、明确标注的完成纪念物与居民后续台词。 | 账号、云存档、经济系统。 |

## 精修验收标准

精修后应以 5–8 名非技术试玩者而不是“画面更漂亮”判断是否成功。[2] 喷泉任务完成后，至少检查以下四句话是否自然出现：

| 追问 | 通过回答 |
| --- | --- |
| “你为什么先让 Pi 去那里？” | 提到乐谱、浮标、风铃或自己的假设，而非“它在发光”。 |
| “Pi 为什么后来去工具坊？” | “它把两件带回来的东西放在一起，才知道要这样做。” |
| “去风铃巷算错了吗？” | “不是；它知道不是风，还带回了一个线索。” |
| “刚才的故事和真实 Pi 是一回事吗？” | “故事是例子；真实 Pi 也会把结果带回来再决定，但得去档案馆看另一个真实例子。” |
