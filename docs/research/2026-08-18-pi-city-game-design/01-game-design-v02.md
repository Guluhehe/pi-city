# Pi City 游戏设计 v0.2：一座让 Pi 学会“把事办好”的城市

**定位：** 面向非技术用户的轻量城市任务冒险。玩家陪小助手 Pi 帮居民完成真实的小愿望，在一次次“看看、动手、带回新发现、确认、回信”的来回中，直觉理解 Pi 不只是聊天，而会记得、会使用工具、会因新结果改变下一步。技术词与真实 Trace 仅作为可选的第二层探索。

> **设计北极星：** 玩家离开时不一定会说出 “Context” 或 “Tool Result”，但应能自然地说出：“Pi 会先去看看；做完后还会把新发现带回来想一想；确认真的好了才会告诉你。”

本版本以高可玩性为**待验证假设**，而不是承诺。它用小任务、路线选择、可选发现、城市变化和温和绕路来建立反复游玩的理由；每一项都必须经灰盒试玩验证后才值得投入美术与 3D 制作。

## 1. 游戏承诺与边界

Pi City 的第一层不是编程教学，也不是 Agent 控制台，而是一座可以被帮助、被记住、逐渐变亮的城市。玩家的角色是 Pi 的 **城市搭档**。他们不输入提示词、不调试、不优化分数；他们只在 Pi 回到思考塔时，帮助它决定下一趟去哪儿、要带什么发现回来、以及现在是否已经可以回信。

| 必须做到 | 必须避免 |
|---|---|
| 让玩家以故事与城市常识理解 Pi 的流程。 | 让玩家阅读 JSON、代码、工具参数或状态图。 |
| 每局 2–4 分钟，并在 15 秒内开始第一个可理解的动作。 | 用长教程、复杂任务栏或四层菜单解释系统。 |
| 让每次绕路产生有趣的城市小反应与可理解的新线索。 | Game Over、扣分、损失进度、羞辱式“答错”。 |
| 为好奇玩家提供真实 Trace Explorer 的可选入口。 | 把 Trace Explorer 当作所有人必须先学会的入口。 |
| 让城市的变化记录玩家帮人办成的事。 | 用通用货币、经验条或装备稀有度代替情感进度。 |

## 2. 核心玩法：Pi 的五站小旅行

每件居民委托都是一张 **心愿单**。Pi 从心愿码头出发，抵达中央的思考塔；之后玩家以地图点击方式让 Pi 在 2–3 个地点中选择下一站。每一站都只有一个自然语言动作和一种容易识别的发现物。玩家的真实动作是“安排 Pi 的下一趟小旅行”，而不是操作抽象流程。

| 地点 | 面向玩家的动作 | Pi 从这里带回什么 | 对应的 Pi 行为，仅在可选复盘中揭示 |
|---|---|---|---|
| 心愿码头 | 听听居民想做什么。 | 心愿信封。 | Request |
| 旧日图书馆 | 想想以前发生过什么。 | 相册页或旧便签。 | Session / memory |
| 观察台 | 去看看现在怎么回事。 | 线索卡或照片。 | Read / inspect tool |
| 工具坊 | 试着帮忙做点什么。 | 徽章、零件或回执。 | Action tool result |
| 暮色花园 | 再确认一下。 | 萤火印章。 | Verify |
| 回信码头 | 把消息送回去。 | 感谢纸船。 | Final answer |

Pi 的一局永远遵循同一个心跳，但并不总以同一顺序出现：**居民请求 → Pi 想想 → 玩家指一站 → Pi 带回发现 → Pi 再想 → 玩家再指一站 → 城市回应 → 居民收到结果。** 一致的心跳建立可理解性；情景、物件和路线差异建立新鲜感。Chants of Sennaar 的经验表明，玩家可以通过在不同情境中反复遇见同一规则并校正假设，逐渐学会抽象系统；Pi City 应让每个 Pi 原理重复出现，但永远包裹在新的居民故事中。[1]

## 3. 任务语法：每局都可玩、可变、可读

每个任务使用同一份作者工具模板，避免策划只靠写对白堆内容。模板迫使每局有主目标、最低路线、可选发现、温和绕路和城市变化。

| 任务元素 | 最小要求 | 作用 |
|---|---|---|
| 居民愿望 | 一句能被孩子理解的请求。 | 让玩家关心结果，而不是流程。 |
| 最低路线 | 2–4 次地点选择即可完成。 | 保证短局节奏和首次通关。 |
| 一个关键发现 | 改变 Pi 接下来可理解／可做的事。 | 让“工具结果影响下一步”真实发生。 |
| 一个可选发现 | 不影响通关，却解释角色或城市。 | 提供探索与重玩，而不是拖时长。 |
| 一次温和绕路 | 早回答、漏带发现或看错重点。 | 用世界后果教 Pi 原理。 |
| 一个永久小变化 | 灯、邮箱、花坛、角色关系或街区道路。 | 把短局汇成长期城市。 |
| 一张可选复盘卡 | 一句无术语总结及“想看看幕后吗？”入口。 | 让学习主动发生。 |

任务制作时必须先写“玩家在 90 秒后应能说出的句子”，再写地点和对白。例如，《灯塔还亮着吗？》的目标句是“修好了也要确认，才知道能不能回信”；《两把钥匙》的目标句是“新发现有时会让 Pi 换一个想法”。如果一局不能对应一个朴素句子，就说明它的教学与玩法没有合在一起。

## 4. 第一季：十二个小委托与 Pi 学习轨迹

第一季不是“十二节 Pi 课”。它是一段城市从不太敢把事交给 Pi，到愿意在雨夜托付它更多工作的成长故事。每个篇章只增加一个新现象，先以故事呈现，再在后续任务中以不同角度重复。这样既遵循隐性学习，也避免玩家被术语淹没。[1]

### 第一章：第一次把事办好（任务 01–03）

| 任务 | 居民愿望与表层故事 | 新的路线／发现 | 玩家自然学到的 Pi 直觉 | 城市变化 |
|---|---|---|---|---|
| 01 灯塔还亮着吗？ | 露露想让月光游行前的灯塔保持明亮。 | 观察定时齿轮 → 修理 → 花园确认。 | 先看看；做过也要确认。 | 灯塔与游行码头点亮。 |
| 02 迷路的邮包 | 邮差把一封生日信送错街区。 | 图书馆的旧地址与观察台的新门牌，任选先后。 | 以前的事能帮助现在，但要对照眼前情况。 | 邮局挂上“Pi 路线图”。 |
| 03 只会唱半首歌的喷泉 | 音乐喷泉启动后只唱第一句。 | 工具坊带回新节拍；必须送回思考塔才能看懂下一站。 | 新结果要带回来再想一次。 | 广场出现可以互动的晚间音乐。 |

第一章只让玩家看到“地点—发现—回到思考塔”的基础节奏。Pi 的小包没有容量限制，所有路线都是温和的，目的不是挑战，而是让操作和城市语言变得熟悉。

### 第二章：Pi 会记得，也会重新想（任务 04–06）

| 任务 | 居民愿望与表层故事 | 新的路线／发现 | 玩家自然学到的 Pi 直觉 | 城市变化 |
|---|---|---|---|---|
| 04 找不到家的小风筝 | 小孩只记得风筝曾落在“有红门的地方”。 | 图书馆回忆与高处观察互相补充。 | 记忆是一条线索，不必是最终答案。 | 屋顶之间出现风筝绳和快捷小路。 |
| 05 两把钥匙 | 图书管理员和修理师各有一把看似正确的钥匙。 | 先验证其中一把会带来不同对话与新线索。 | 新证据可以让 Pi 放下第一种猜法。 | 档案馆多了一扇可进入的小门。 |
| 06 雨天的露天电影 | 电影要开场，却可能下雨。 | 小包第一次只能带两件发现物：雨云照片、旧天气册、借伞回执三选二。 | Pi 不能每次都带上所有东西，要挑此刻有用的。 | 广场增加雨棚与夜间电影。 |

第二章引入 **Pi 的两格小包**。它是一个儿童能理解的物理限制，也是第一处真正的策略：物件不会消失，玩家只是决定这一趟带哪两样回思考塔。玩家因此感受到信息选择会改变下一步，而不会看到“上下文预算”这种术语。这个设计借鉴了 Unpacking 的轻量摩擦与 Wilmot’s Warehouse 的自然分类乐趣，但不加入分数、罚时或唯一最优摆放。[5] [6]

### 第三章：Pi 会动手，也会认真收尾（任务 07–09）

| 任务 | 居民愿望与表层故事 | 新的路线／发现 | 玩家自然学到的 Pi 直觉 | 城市变化 |
|---|---|---|---|---|
| 07 花园里醒不过来的种子 | 园丁想让夜花在庆典前开放。 | 观察不同光线、请工具坊调温、到花园确认。 | 行动的结果必须被看见，才能确定真的有效。 | 城市出现夜花花坛。 |
| 08 一张没有署名的感谢卡 | 两位居民都以为卡片写给自己。 | 阅读旧照片、寻找笔迹、带回新发现后改变 Pi 的送信路线。 | Pi 不只是照第一眼看到的线索行动，会重估。 | 邮局墙上出现“谢谢你”的卡片展。 |
| 09 风车的秘密时间 | 风车每隔一段时间就停下。 | 玩家可以走“快路线”修好当前齿轮，或走“慢路线”找出重复停转原因。 | 有时眼前的问题和真正的原因不是一件事。 | 风车成为可远眺的地标与城市风向提示。 |

第三章使“确认”不再只是一站固定的暮色花园，而成为不同故事中的可观察行动。TOEM 的经验提示：单一核心交互可以在独立小场景中获得充分变化，只要每个场景都有值得关注的对象，并让角色对玩家带回的内容作出具体反应。[2]

### 第四章：更多人开始相信 Pi（任务 10–12）

| 任务 | 居民愿望与表层故事 | 新的路线／发现 | 玩家自然学到的 Pi 直觉 | 城市变化 |
|---|---|---|---|---|
| 10 同一晚的两张心愿单 | 面包师缺送货路线，乐队缺演出海报。 | 玩家决定先处理哪件；另一件会获得角色化的等待反馈。 | Pi 能安排先后，顺序会改变这一次的城市节奏。 | 市场与剧场分别开放新活动。 |
| 11 海雾里的船铃 | 港口雾大，居民的线索互相矛盾。 | 玩家先选可信的观察来源，再用新结果校正。 | Pi 面对不一致的信息要继续查，而不是假装确定。 | 港口出现雾灯与船铃小游戏。 |
| 12 星光节的最后一盏灯 | 全城各处的小成果汇成一次节日任务。 | 可使用前面街区形成的快捷路径与居民帮助；仍不要求技术操作。 | Pi 的记忆、工具、确认和回应连接成一整条办事能力。 | 星光节、完整信任图、Pi 后台档案馆开放。 |

第四章的两个委托并不是复杂调度游戏。玩家仍只面对 2–3 个自然路线，却第一次感到“先帮谁”会改变另一位居民的对白、城市氛围和可选发现。Alba 的小帮助汇聚为清晰公共目标的结构，适合承载这种温和的长期动机。[4]

## 5. 路线选择如何保持可玩，而不成为固定动画

高可玩性不来自堆更多城市地点，而来自让每次“下一站”满足三个条件：**玩家能理解为何选它；不选也能看到不同后果；结果会带来新的判断。** 因此每个任务最多只在一个时刻提供真正分叉，其他时刻保持清楚引导。

| 选择类型 | 玩家表层想法 | 设计中的真实作用 | 可接受结果 |
|---|---|---|---|
| 先看还是先做 | “要不要先弄清楚？” | 教观察先于行动。 | 先做会多一段小绕路，不会失败。 |
| 带哪两件东西 | “Pi 的小包该装什么？” | 教选择性携带信息。 | 两条路线都可完成，但会开启不同线索。 |
| 相信旧记忆还是新发现 | “哪个更像是真的？” | 教记忆与新结果需要对照。 | 先选错会得到反证并修正。 |
| 快速修好还是找真正原因 | “现在帮到，还是帮得更稳？” | 教短期结果与验证／深入观察。 | 都可得到感谢，但城市变化不同。 |
| 先帮谁 | “今晚谁更急？” | 教任务优先次序和情感后果。 | 两人都能被帮助，等待者有可读反应。 |

每一局的选择不应被标成“好”“坏”“高分”“低分”。系统只记录玩家走过的路线，在任务相册里留下两张不同的“Pi 今天学到什么”明信片。这样会鼓励重玩与讨论，而不会把轻量体验变成考试。

## 6. 城市成长：信任图、发现册与后台档案馆

城市的长期进度由三层组成，分别服务情感、重玩和学习，而不是用通用货币混在一起。

| 成长层 | 玩家看见什么 | 由什么触发 | 它回答什么 |
|---|---|---|---|
| 信任图 | 街灯、邮局、广场、花园、港口逐渐恢复；居民开始主动向 Pi 求助。 | 主线任务完成。 | “我帮这个城市带来了什么？” |
| 发现册 | 居民照片、Pi 的小物件、未走路线的小秘密。 | 可选发现、不同路线、重玩。 | “还有什么故事没看见？” |
| 后台档案馆 | 任务中的城市物件与 Pi 概念对应；随后可查看同类真实 Trace。 | 主动点击“Pi 原来是这样想的”。 | “这件可爱的事在真正的 Pi 里发生了什么？” |

发现册比排行榜更适合这个产品。它既能提供完成欲，又不把人的善意委托量化成效率。Unpacking 的开发经验表明，和平、个人化的体验不必靠分数或评级来提供回报；Pi City 应将这一原则延续到城市成长。[5]

## 7. 学习设计：不教术语，但让概念变得可说

| Pi 现象 | 玩家先遇到的故事体验 | 第二次出现的变化 | 可选术语卡的最短说法 |
|---|---|---|---|
| 请求 | 居民带来一张心愿单。 | 两张同时到港。 | “Pi 先听清你想办什么。” |
| 记忆 | 旧照片或旧地址有帮助。 | 旧记忆与新观察矛盾。 | “Pi 会带着之前的谈话继续办事。” |
| 观察 | 望远镜看见当前情况。 | 同一物件从不同位置看有不同线索。 | “Pi 可以先查看信息，不必马上猜。” |
| 工具行动 | 工具坊真的修了一样东西。 | 工具带回意外结果。 | “Pi 能用工具去做事。” |
| 结果回流 | 徽章回到思考塔。 | 新结果改变原来的路线。 | “工具做完后，结果会回来影响 Pi 的下一步。” |
| 验证 | 灯塔在傍晚真的亮着。 | 快速修好与彻底确认形成区别。 | “Pi 会确认结果，而不只说它做过。” |
| 优先级 | 两位居民等待。 | 城市成果形成快捷路线。 | “Pi 也会安排先做哪一件事。” |

每张术语卡都遵循“三句上限”：一句讲城市中刚发生的事，一句讲 Pi 的行为，一句邀请前往档案馆。卡片绝不出现 token、参数、schema 或未解释的工程词。真正技术用户可从档案馆继续深入；普通玩家到这里已经形成正确且足够的心智模型。

## 8. 首个灰盒原型：不要先做十二局

第一轮只制作三个任务的灰盒：《灯塔还亮着吗？》《迷路的邮包》《只会唱半首歌的喷泉》。它们合起来验证 Pi City 最重要的三件事：玩家能否理解“先看”，能否感受到“旧信息也有用”，以及能否注意到“新结果要回来再想”。

| 原型范围 | 必须实现 | 明确不做 |
|---|---|---|
| 地图 | 5 个固定地点、Pi 小车路线、1 个中央思考塔。 | 全城自由漫游、复杂 3D 角色控制。 |
| 互动 | 点击下一站、查看发现物、可选小秘密。 | 自由输入、背包排序、多层菜单。 |
| 内容 | 3 个任务、每个 1 条主线 + 1 个温和绕路 + 1 个可选发现。 | 完整十二任务、动态生成任务、随机谜题。 |
| 反馈 | 地点亮起、物件回到塔内、居民小反应、街区微变化。 | 分数、金币、倒计时、失败页。 |
| 学习 | 每局一张可跳过的无术语复盘卡。 | 强制技术课、真实 Trace 的必读解释。 |

试玩的首要指标不是完成率或平均时长，而是玩家能否以自己的话复述发生了什么。首局后只问：**“Pi 为什么没有一看到问题就回信？”** 第三局后只问：**“为什么 Pi 要把喷泉带回来的新节拍先放进思考塔？”** 若玩家不懂这两个问题，应该重做地图反馈、对白和物件表现，而不是增加更多内容。

## 9. 与现有 Pi City 的关系

现有城市世界、Arrival / Session / Context / Model / Tool 的空间隐喻、Story 与 Evidence Explorer 都可被保留，但需要重新排序。故事游戏成为前台；真实 Trace Explorer 变成面向好奇玩家的后台档案馆。教学任务使用作者定义的、明确标记为 tutorial scenario 的事件，永远不伪装成导入的真实运行；当玩家主动下潜时，才展示真实或脱敏的同类 Pi Trace。这既保留项目的 evidence-honest 原则，也让它拥有非技术玩家真正愿意跨入的入口。[7]
